### 2.6 直接回答两个点名项

- **`playback-allowance` 是不是服务端配额？**
  不是 StoreKit 商品，也不是服务端配额。它是「本地每日免费播放额度」体系：OSLog subsystem `tv.rexnow.app.playback-allowance` + 本地签名账本（`localGrants`/`journalSignature`/`dailyLimit`/`IsIntegrityProbe`），文案明确写「本机播放额度」。服务端只做 **lease（每次播放的租约）** 与 **report（用量上报）**。★★★
- **`CloudProofKey` 是不是服务端凭证？**
  不是订阅凭证，是**设备证明密钥**：`CloudProofKey` 持 P-256 公钥 JWK（`{"crv":"P-256","kty":"EC","x":"…`），私钥在 Secure Enclave（`CryptoKit.SecureEnclave.P256.Signing.PrivateKey`），用于给每个请求签 `rex-request-proof+jwt`。它不"发权限"，但**它是所有授权请求的门票**：没有它签不出 proof，服务端一律 `attestation_required` / `proof_unavailable`。★★★

## 4. 可解锁分级

分级口径：
- **A**：纯客户端布尔/明文判断，Loon 改一个响应字段或一次 hook 即通吃。
- **B**：Apple 签名本地校验（StoreKit 2 JWS / receipt），无强服务端绑定；本地补丁可行，Loon 一般无效。
- **C**：权限由服务端签发、客户端用设备密钥验签/带证明；改包/改响应都无法伪造，只能等真授权。

### Rex = **C（强 C，不建议投入）**

| 判据 | 证据 | 结论 |
|---|---|---|
| 授权是服务端签发的 JWS | `{"alg":"ES256","kid":"rex-lic-1","typ":"rex-license+jwt"}` + payload `{"app":"rex","deviceId"…,"via":"storekit","lifetime":true,"validUntil":…}` | 改包改不出签名 ★★★ |
| 每个请求要设备密钥签 proof | `rex-request-proof+jwt`、`proofKeyThumbprint`、`CryptoKit.SecureEnclave.P256.Signing` | 私钥不可导出 ★★★ |
| 设备级 App Attest | `DCAppAttestService`、`/api/device/attestation/`、`X-Rex-Attest-Trace`、`attestation_required` | 模拟器/改机直接被拒 ★★★ |
| 播放要服务端 lease（高画质路径） | `RexPlaybackLeaseCoordinator` / `RexPlaybackLeaseGrant` / `RexPlaybackLeaseVerifier` / `RexPlaybackLeasePayload` / `PendingLease`；`/api/license/playback/{challenge,lease,claim,report}` | 租约 payload 有 Verifier 验签；无合法 lease 高画质路径走不通（本地普通 MP4 是否强制 lease 未逐一验证，按符号看是"按播放路径分级"的） ★★★/★ |
| 传输层固定 | Info.plist `NSPinnedDomains api.rexnow.tv` 双 SPKI pin | MITM 直接握手失败 ★★★ |
| 设备上限 | `binding{maxDevices, devices[], assisted, current}` + PIN 批准流 | 多设备共享也被限 ★★★ |

**能解的只有"UI 层"**（把 `RexProStore` 的已购标志点亮、隐藏付费墙），播放入口依然会在 lease 处被拦，属于负收益。

## 5. 务实落点

### 5.1 Loon 改哪里（结论：改不动授权）

- 目标域名只有三个有意义：`api.rexnow.tv`（授权/租赁）、`auth.rexnow.tv`（账号）、`feedback.rexnow.tv`（无关）。
- `api.rexnow.tv` 被 **ATS SPKI pin** 锁死：Loon 的 MITM 证书链对不上 `C5+lpZ7…` / `fk6IOKi…` 两个 pin，握手即失败。想在 Loon 里 `reject`/`script` 这个域名，效果等于断网，不是解锁。
- 即使绕过 pin（越狱装 SSL Kill Switch 之类），响应体是 **ES256 JWS**（`kid: rex-lic-1`）：`validUntil`/`lifetime`/`deviceId` 都在签名覆盖范围内，改字段 → 验签失败 → `pro.purchase.unverified` / `activation.invalid`。
- 有用的字段根本不在响应里，而在**请求**里：`X-Rex-Request-Proof`（设备签）、`deviceCheckToken`（App Attest）。Loon 无法生成。

**因此：Loon 对 Rex 的 Pro 无可用面。** 唯一还能做的，是把非授权域名（TMDB 图片、字幕源、115 中转下载 URL）做重写/加速，与解锁无关。

### 5.2 若要本地补丁（越狱/TrollStore 路线）

按阻力从低到高：

1. `RexProStore` / `RexProEntitlement` 的已购读取点——只影响 UI 与本地功能开关（`settings.license.*` 界面会显示「本设备已获得授权」）。
2. `RexPlaybackDailyAllowance` 的本地账本（`localGrantConsumptions` / `journalSignature`）——可把 3 次/天改大，但 `isIntegrityProbe` + `kern.bootsessionuuid` 会检测替换，且账本 digest 对不上会走 `paid.playback.storage.failed`。
3. 播放入口 `RexPlaybackLeaseCoordinator` 的 lease 校验——这里一旦放行，等于彻底关掉授权；但服务端 `report` 仍会记录 `deviceId`，账号侧可能被标记 `account_changed`/`revoked`。

**卡点（一句话）**：Pro 的真实凭证是「服务端 ES256 签名的 license JWS + 每次播放的 lease」，签名私钥在服务端、请求证明私钥在 Secure Enclave、传输还做 SPKI pin——三层都不在客户端可控范围内。这不是"改个字段"的问题，是"要不要伪造 Apple 级签名"的问题。
