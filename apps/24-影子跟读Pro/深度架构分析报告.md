# 24-影子跟读Pro 深度架构分析报告

## 1. 技术栈判定
- **架构范式**：采用典型的跨平台 Flutter (Dart AOT) 架构。主工程由 `Flutter.framework` 运行时与承载业务逻辑的 `App.framework` 构成，iOS 原生工程仅作为轻量宿主容器（Runner 壳工程）。
- **播放内核**：采用极高规格的播放引擎组合。主播放器采用 Flutter 顶级的 `media_kit` 方案（`MediaKitVideoPlugin` 桥接），底层直接由 `Mpv.framework`（mpv 内核）、`ffmpegkit.framework`、`Ass.framework`（libass 渲染）、`Harfbuzz.framework` 及 `Dav1d.framework` 驱动；轻量音频播放依托 `audioplayers` 插件（`AudioPlayersStreamHandler`）；内嵌火山引擎媒体组件（`TTSDKPlayerCoreLiveLite.framework`）。
- **端侧 AI 与 ASR 引擎**：集成端侧离线语音识别框架 `sherpa_onnx.framework`，通过 `FlutterOnnxruntimePlugin` 在端侧运行 ONNX 模型，实现离线跟读打分。
- **商业化 SDK**：原生层集成穿山甲 GroMore / Pangle 聚合广告套件（`CSJAdSDK.bundle`, `ABU...`, `CSJ...`），并通过 `SwiftPangleFlutterPlugin` 暴露给 Dart。
- **规模**：主二进制 70.20 MB，包内文件 1040 个；原生类 1176 个，应用源文件 1787 条，内嵌库源文件 213 条，动态框架达 42 个。

## 2. 模块分层
核心业务状态流与 UI 组件全部编译至 Dart AOT 二进制中，原生层呈现为“Flutter 宿主与插件交互分层”：
- **宿主与导航层**：原生生命周期托管与通道。代表类：`AppDelegate`、`FlutterAppDelegate`、`FlutterMethodChannel`、`FlutterEventChannel`。
- **播放引擎层**：跨平台媒体管道封装。代表类：`MediaKitVideoPlugin`（mpv 纹理桥接插件）、`MediaKitLibsIosVideoPlugin`、`SwiftAudioplayersDarwinPlugin`、`AudioPlayersStreamHandler`。
- **业务服务与插件层**：端侧 AI 与基础能力桥接。代表类：`FlutterOnnxruntimePlugin`（ONNX 端侧推理桥接）、`RecordIosPlugin`（录音采集插件）、`InAppPurchasePlugin`（内购订阅插件）、`ConnectivityPlusPlugin`。
- **算法与数据模型层**：端侧语言模型与存储支撑。代表类：`ArrayBigramModel`、`CompactLoudsNgramModel`（离线语言模型）、`CSJAdStorageManager`。
- **UI 容器与原生视图层**：原生媒体选取与平台视图扩展。代表类：`FlutterPlatformView`、`DKPhotoPlayerPreviewVC`（媒体预览）、`DKPhotoImagePreviewVC`、`BannerViewFactory`。

## 3. 能力模块
- **播放与多音轨**：基于 `media_kit` + `Mpv.framework`，原生支持 MKV/MP4/H.265/AV1 全格式硬解与软解，具备毫秒级 A-B 循环播放能力，支持在 Flutter 界面中动态切换音轨。
- **字幕渲染**：依托底层 `Ass.framework` 与 `Harfbuzz` 进行特效字幕栅格化，在 Flutter 视图中渲染同步双语对照字幕与逐词高亮。
- **跟读录音与评分**：录音模块由 `RecordIosPlugin` 负责原声低延迟采集；核心亮点是集成 `sherpa_onnx.framework`，通过 `FlutterOnnxruntimePlugin` 在端侧调度离线 ASR 模型进行语音特征比对与发音打分，零网络延迟。
- **词汇与记忆算法**：内置 `BigramModel` 与 `CompactLoudsNgramModel` 辅助端侧语音识别文本校正，上层由 Dart 维护跟读打卡记录与复习间隔。
- **AI / ASR 能力**：全盘采用端侧离线 AI 架构（sherpa-onnx + onnxruntime），不依赖外部收费 ASR 云接口，极大保障用户录音隐私与弱网可用性。
- **导入导出**：集成 `DKImagePickerController` 与相册/文件插件，支持导入本地相册视频并提取音频生成跟读任务。

## 4. 网络与 API 契约
- **离线化特征**：属于“重端侧、弱中心”的离线工具架构，Recon 结果显示无自有业务 API 域名（`0 个自有域名`）。
- **依赖接口职责**：网络请求主要流向两部分：
  1. 苹果官方 App Store 验证通道（`InAppPurchasePlugin` 处理内购订阅）。
  2. 穿山甲 / GroMore 广告联盟接口（广告下发、策略曝光与收益回传）。
- **业务闭环**：音视频解码、语音识别、发音评分及字幕解析均在本地完成，无须后端依赖。

## 5. 源文件拓扑
- **主工程结构**：应用核心代码为纯 Dart 实现，已固化入 `App.framework`，因此编译期 `#file` 路径中不展现 `.dart` 业务文件。
- **三方与内嵌库区隔**：源文件列表主要由庞大的底层 C/C++ 依赖构成：
  - `/tensorflow/lite/kernels`（TFLite 算子路径，128 条）。
  - `/openssl/boringssl/src`（BoringSSL 密码库，169 条）。
  - `/KleidiAI/kai/ukernels`（Arm CPU 推理加速算子，92 条）。
  - `/1/s/onnxruntime`（ONNX 计算图与算子，33 条）。
- **符号甄别**：原生类表中有超 60% 类名属于穿山甲广告组件（`CSJ...` / `ABU...`），需严格将其与 `Flutter...Plugin` 核心桥接层及音视频库分离。

## 6. 对自研的参考价值
1. **Flutter 多媒体选型范式**：验证了 Flutter 跨平台体系下，`media_kit`（libmpv + libass）是兼顾全格式播放、极低延迟 seek 与 ASS 特效字幕的最佳实践。
2. **端侧离线 ASR 落地**：引入 `sherpa_onnx + onnxruntime` 实现了高精度端侧跟读打分，消除云端 ASR 成本与延迟，极具借鉴意义。
3. **架构极简与纯离线**：无需自建庞大后端矩阵，聚焦端侧媒体处理与 AI 推理，大幅降低早期运维成本。
