### 1.2 硬解

- 主路径：mpv `hwdec=auto` + **VideoToolbox**（`videotoolbox` 出现 28 次、`VideoToolbox` 39 次、`VIDEOTOOLBOX` 大写常量）。★★★
- 用户可见开关（`zh-Hans` 原文）：★★★
  - `hardDecode = 硬解码(HW/GPU)`
  - `decodeModeTips = 硬解码：高效省电…软解码：兼容性强…除非无法正常播放，否则不要使用软解码！`
  - `switchHardDecode / switchHardDecodeFailed = 当前设备不支持硬解码该视频`
- **硬解是 Pro 权益之一**（见 §2.1），关闭 Pro 后强制软解——这正是用户最在意的"硬解"点。

### 1.3 HDR / 杜比视界

- `p_HDR = HDR视频播放`（Pro 权益项）；`HDRTag`、`hdrMetadata = HDR元数据`、`hdrSubtitle / hdrSubtitleExposure = HDR字幕/HDR字幕亮度`。★★★
- `sdrMappingHDR = SDR转HDR`，`sdrToHDRDescription = 适用于峰值亮度超过1000nits的HDR屏幕` → 反向 tone-mapping（SDR→HDR 上变换）。★★★
- `enableHDRVivid = HDR Vivid` + `enableHDRVividTips = 支持HDR Vivid逐帧动态元数据`（中国 HDR Vivid 标准）。★★★
- `enableDolbyP7FEL = 杜比P7启用FEL`、`enableDolbyP7ToP81 = 杜比P7转杜比P8.1`。★★★

### 1.4 音轨直通

- `enableDolbyAtmos = 杜比全景声`；`enableDolbyAtmosTips = 支持原生杜比 E-AC3 Atmos 音频透传，但切换倍速有略微延迟`。★★★
- 代码侧：`platformAllowEAC3` / `routeAllowEAC3` / `speedDisablesEAC3` 三个判定（平台能力、输出路由、倍速时禁用透传）→ 说明实现是**真·EAC3 位流直通**，并按路由/倍速降级。★★★
- `audioProfile = 音频规格`，`audioNormalizeDownmix`（音量归一/下混）。

### 1.5 技术栈与扩展

- Swift + UIKit（`PurchaseView`、`ServerProvider` 等大量 VC）；Combine；Core Data + **CloudKit**（`NSPersistentCloudKitContainer`、容器 `iCloud.com.wuziqi.SenPlayer`）；App Group `group.com.wuziqi.SenPlayer`（TV/Mac 共享）。★★★
- 自有模块化 SDK：`DriveKit`（云盘）、`FilesProvider`（协议层）、`ServerKit`（媒体服务器）、`EmbyKit`、`DLNAKit`、`SenLib`。★★★
- FirebaseAnalytics / GoogleAppMeasurement / Crashlytics（分析）；无第三方支付 SDK。
- **无 App Extension**；**无越狱/反调试检测**（全包未命中 IOSSecuritySuite / Cydia / Substrate / Frida 关键字）。★★★

## 4. 可解锁分级

分级口径同 Rex 档：**A** 明文/布尔判断；**B** 本地签名校验但无服务端绑定（可本地补丁）；**C** 服务端签发 + 设备证明（不可伪造）。

### SenPlayer = **B（可本地补丁；Loon 完全无效）**

| 判据 | 证据 | 结论 |
|---|---|---|
| 授权判定在客户端 | 5 个 `proLifeId_*_isPro` 布尔 + `ProPublish.isPro` | 可 hook/改 ★★★ |
| 无授权服务器 | 全包无收据校验/授权域名，仅 `senmuse.com/api/logs` | Loon 无处下手 ★★★ |
| 校验来自 Apple 本地 JWS | `Transaction.currentEntitlement(for:)`（StoreKit 2） | 不能"生成"新交易，但可绕过读取 ★★★ |
| 无越狱/反调试检测 | 未命中 IOSSecuritySuite / Cydia / Substrate / Frida | 补丁无对抗 ★★★ |
| 有"已购数据"落地 | `saveVerifyData(isPro:)` + `verifyExpirationDate(expirationDay:)` | 需同时处理，否则重启被覆盖 ★★ |

**注**：B 级不等于"改个 plist 就行"。因为每次启动 `StoreKit2Manager` 会重算 `saveVerifyData` 并覆盖 `proLifeId_*_isPro`，纯改 UserDefaults 会在下次校验时被打回；稳定做法是 hook `ProPublish.isPro` 的 getter（或 `StoreKit2Manager` 的判定函数），让所有读取点统一返回 true。

## 5. 务实落点

### 5.1 Loon

- **没有可改的域名/字段**。SenPlayer 没有任何"服务端说你是不是 Pro"的请求，Loon 的 `http-response` 脚本没有任何可篡改的 JSON 字段。
- 唯一相关的 Loon 用途：`forceProxyToPlayKernel` 打开后，让 mpv/FFmpeg 的播放流量走系统代理（Tun），可做 SMB/WebDAV/直链的抓包与改流（比如把网盘直链重写到自建反代提速），**与 Pro 无关**。

### 5.2 本地补丁（推荐路线，门槛最低的三者之一）

优先级：

1. **`ProPublish.isPro` getter**（一处改，全 UI + 播放器生效）。风险：`ProPublish` 是 Swift `@Published`，需 hook 属性 getter 或 `objectWillChange` 上游。
2. `StoreKit2Manager` 的已购判定（`saveVerifyData(isPro:)` 的入参、`verifyExpirationDate(expirationDay:)` 的返回）。
3. 兜底：直接改 UserDefaults 的 5 个 `proLifeId_*_isPro`（简单但每次启动会被 StoreKit 校验覆盖，只适合快速验证）。

### 5.3 结论

- 三者中 **SenPlayer 是唯一"纯本地、无服务端、无反调试"的**，性价比最高。
- 但要注意：它把 **硬解、HDR/杜比/Atmos 直通** 全部锁在 Pro 后面，所以"解开 Pro"= 真正解锁画质，收益是三者中最大的。
- REX 与 VidHub 的对照见同目录另两份档案。
