### 2.2 判定链（三段式：本地收据 → 服务端校验 → 账号授权）

```
① 本地收据
   SKReceiptRefreshRequest（ReceiptHelper.refreshReceiptRequest）
   └─> ReceiptHelper.validateReceipts() / getValidReceiptExpireDate()
       日志: [IAPHelper] validateReceiptState / ExpiredSubscription / RefundedSubscription
       错误串: "Receipt not signed by Apple." "Receipt bundle identifier does not match…" "The receipt is not in PKCS7 format."

② 服务端校验（Apple App Store Server API 代验）
   [IAPHelper] validate assa → [IAPHelper] call Assa Server
   callAssaServerApi got this transaction is Illegal → "set current life time vip status to false"
   callAssaServerApi got this transaction is refunded → "set current life time vip status to false"
   callAssaServerApi success → IAPHelperPurchaseNotification

③ 账号授权（跨平台/跨端的关键）
   ReceiptHelper.associateLicensesWithReceipt()  → POST https://vh.verify.okaapps.com/api/v1/licenses/apple
       需 accessToken（未登录直接失败："associateLicensesWithReceipt failed with no accessToken"）
   LicensesHelper.getLicenses() → GET https://vh.verify.okaapps.com/api/v1/licenses
       结果加密后写 UserDefaults + Keychain（"Failed to decrypt and decode licenses from UD/KC"）
```

### 2.6 未定项与验证方案（诚实标注）

未能在此预算内完成反编译，以下两点仍需实证：

1. `/api/v1/licenses` 的响应是**明文 JSON** 还是**加密/签名体**。
   - 若是明文：Loon 有理论注入面（见 §5）。
   - 若是加密体（`CryptoSwift`/AES.GCM 已在包内，且 licenses 落地即密文）：Loon 无法构造。
2. `isVIP` 的最终计算点是 `LicensesHelper` 的服务端列表，还是 `IAPHelper` 的本地收据 —— 决定"退网 + 清缓存"能否回落到本地收据。

- 断网启动 → 若 VIP 仍生效 = 有本地收据兜底；若掉 VIP = 纯服务端。
- Loon 挂 `vh.verify.okaapps.com` 抓 `/api/v1/licenses` 响应体 → 看是否可读 JSON、字段是否含 `vip/expire/sign`。

## 4. 可解锁分级

分级口径同前：**A** 明文/布尔；**B** 本地签名校验、无强服务端绑定；**C** 服务端签发、需设备/账号凭证。

### VidHub = **C−（服务端账号绑定 + 强反调试；Loon 只有理论面）**

| 判据 | 证据 | 影响 |
|---|---|---|
| VIP 权威来自服务端 license | `/api/v1/licenses`、`LicensesHelper`、`Logout.Confirm.Title = 退出登录将无法获取VIP状态` | 断网/清缓存即掉 VIP，改本地标志无效 ★★★ |
| 购买必须绑账号 | `associateLicensesWithReceipt failed with no accessToken`、`Licenses.ReboundFailed.Title`、`Login.Tips.Title.Warning`（绑定后不可解绑） | 无法伪造"新购买" ★★★ |
| 服务端代验 Apple 交易 | `callAssaServerApi`（Illegal/refunded 直接置 false） | 假收据过不了 ★★★ |
| 本地缓存是密文 | `CryptoSwift` / `CryptoKit.AES.GCM`；UD/KC 两份密文 | 改缓存需先拿密钥 ★★ |
| 强反调试 | `IOSSecuritySuite`（Jailbreak/FishHook/MSHook/RuntimeHook/Integrity/Proxy/Emulator 全开） | 越狱注入易被识别 ★★★ |
| 有远程配置 | `vh.config.okaapps.com/Vidhub/native_config.json` | 可随时下发风控 ★★ |

**结论**：比 Rex 略软（没有每次播放的服务端 lease、没有 Secure Enclave 逐请求签名），比 SenPlayer 硬得多（服务端账号授权 + 商用反调试套件）。属于"能解但要动真格"的一档。

## 5. 务实落点

### 5.1 Loon 改哪个域名/字段

- **唯一有意义的点**：`vh.verify.okaapps.com` 的 `GET /api/v1/licenses`（以及 `POST /api/v1/licenses/apple`）。
  - 若响应是明文 JSON，理论做法：`http-response` 脚本重写为一份 `VHLicense` 数组，字段形如 `vip=true`、`vipYears=<大数>`、`isVIPE=true`、到期时间拉到 2099。
  - 但前置条件是**已登录并持有 accessToken**（`vh.api.okaapps.com/api/v1/auth/login` 走的账号体系），未登录时 `associateLicensesWithReceipt` 直接失败。
- **明确改不动的地方**：
  - `/api/v1/licenses/apple`：入参是 Apple 收据 + 交易号，服务端用 App Store Server API 反查；改请求体只会得到 `Illegal`，客户端反而把 VIP 置 false（`callAssaServerApi got this transaction is Illegal`）。
  - 本地 licenses 密文（UD/KC）：AES，密钥在客户端但需逆向取得，Loon 够不着。
- **不建议**：对 `vh.api.okaapps.com` 做 MITM。它承载登录与 `server-time`，一旦被检测到异常时间/证书，配合 IOSSecuritySuite 的 `ProxyChecker`（会检测系统代理）容易触发风控。

### 5.2 卡点（一句话）

VidHub 的 VIP 是**账号绑定的服务端 license**，且购买侧由服务端代验 Apple 交易、客户端落地即加密、外层还套了 IOSSecuritySuite——**Loon 要么改不动（响应加密），要么改了也没用（服务端仍是权威）**。

### 5.3 相对性价比

| 维度 | Rex | SenPlayer | VidHub |
|---|---|---|---|
| Loon 可行性 | 无（SPKI pin + 每请求签名 + lease） | 无（无授权域名） | 理论有（`/api/v1/licenses`），但受登录/加密/风控限制 |
| 本地补丁难度 | 极高（Secure Enclave + App Attest） | **低**（纯本地布尔 + 无反调试） | 高（反调试 + 服务端权威） |
| 解锁收益 | 4K/HDR/多库/多环境 | 硬解/HDR/Atmos 直通/帧插值 | 去广告/全平台/HDR 增强 |

**给用户的实用结论**：三个里只有 **SenPlayer** 值得动手（一次补丁解决，且它把硬解与 HDR 直通锁在 Pro 后面，收益最大）。Rex 与 VidHub 都建议直接买——VidHub 终身 VIP 是三者中最便宜的一次性买断。
