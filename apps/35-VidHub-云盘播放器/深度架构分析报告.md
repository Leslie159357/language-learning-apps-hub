# VidHub 深度架构分析报告

## 1. 播放内核与渲染实现
VidHub 采用基于 libmpv 的自研多媒体播放引擎架构，核心由 MPVManager.swift、MPVPlayerManager、MPVNode、MPVFilter 与 OmiMPVSettings 统一调度。
- **硬件解码与渲染流水线**：依托 mpv 内置的 VideoToolbox 硬件解码管线，将视频帧输出到原生渲染容器 MVCoreVideoView 与 MetalRenderView，由 AppRenderCoordinator 进行帧调度控制。
- **色彩与图形呈现**：图像层深度结合 CoreAnimation 与 Metal 渲染，内嵌 CoreTextRenderLayer、ShapeRenderLayer、GradientRenderLayer 与 InvertedMatteLayer 处理界面与滤镜特效。
- **音轨与路由**：音频输出结合 AVAudioSession 与系统音频总线，通过 AudioSelectionControl 提供音轨切换，并支持 AVRoutePickerView 实现 AirPlay 隔空播放。
- **流管道控制**：在数据流进入播放器前，通过 FileProviderStreamTask、FPSStreamTask、StreamDecryptor、StreamEncryptor 及 BlockDecryptor/BlockEncryptor 完成流式解密与传输保护。
- **字幕处理**：字幕获取系统由 ASSubtitleFetcher、SubHDClient、SubHDDownloadSession、SubHDSubtitleDataSource 与 SubtitleSearchView 构成，支持本地 ASS、SRT、VTT 以及 SubHD/OpenSubtitles 在线拉取与 CoreText 渲染。

## 2. 模块分层结构
- **媒体库与持久化层（CoreData / Scrapper / Sync）**：负责资产抓取与库同步。核心类包括 CoreDataStack、MediaScrapper、TMDBSearchResult、SyncEngine、FileObject、ItemsExtension、IndexingError 与 DirtyCloudItemCleaner。
- **播放器控制层（MPV / MVPlayer / PlayerSettings）**：承接播放逻辑与参数配置。核心类包括 MPVManager、MPVPlayerManager、MVPlayerView、MVPlayerViewModel、PlayerControllerCoordinatorView、VideoPlayerVC、ChaptersControl、PlaybackRateControl、AudioSelectionControl、SubtitleSelectionControl 与 ResolutionVersionControl。
- **存储与协议驱动层（FileProviders / QPSLimiter）**：多网盘与协议访问总线。核心类包括 CloudFileProvider、AliyunDriveFileProvider、BaiduDriveFileProvider、Drive115FileProvider、Drive123FileProvider、Drive189FileProvider、Yun139FileProvider、DropboxFileProvider、OneDriveFileProvider、HTTPFileProvider、SynologyFileProvider、WebDAVFileProvider，以及专属频控工厂 AliYunQPSFactory、BaiduDriveQPSFactory、Drive115QPSFactory、Drive123QPSFactory、GuangyaQPSFactory 和 Yun139QPSFactory。
- **UI 与视图呈现层（Home / Control / Settings）**：视图组织与交互界面。核心类包括 HomeVC、MVHostingController、PlayerUISettingsVC、ControlViewBuilder、SubtitleSearchView、SynologyLoginModeCell、EmptyDataSetView、MediaRatingsView 及多云盘扩容升级视图（AliyunUpgradeBottomView、Drive115UpgradeBottomView、Drive123UpgradeBottomView）。

## 3. 协议与云盘接入
- **局域网与私有服务**：全面支持 WebDAV（WebDAVFileProvider）、群晖（SynologyFileProvider，接入 global.quickconnect.cn 与 global.quickconnect.to）、Plex（通过 app.plex.tv 与 plex.tv/api/v2 交互）以及 Emby（EmbySubtitleCoordinator）。
- **主流网盘接入**：原生对接阿里云盘（AliyunDriveFileProvider）、百度网盘（BaiduDriveFileProvider）、115网盘（Drive115FileProvider、Drive115QRCodePoller）、123云盘（Drive123FileProvider）、天翼云盘（Drive189FileProvider、Drive189Sign）、中国移动云盘（Yun139FileProvider）、华为云盘、广雅云盘、Dropbox、Google Drive、OneDrive 与 PikPak（dav.mypikpak.com）。
- **OAuth 鉴权域名与统一跳转**：
  - 授权中转网关：自建 zh.okaapps.com/redirect_115、okaapps.com/redirect_plex?code=，以及华为网盘回调 vh.api.okaapps.com/api/v1/auth/callbacks/huawei-login。
  - 115网盘：passportapi.115.com/open/authorize 与 open/refreshToken。
  - 百度网盘：openapi.baidu.com/oauth/2.0/token 与 pan.baidu.com/rest/2.0/xpan/file。
  - 阿里云盘：openapi.aliyundrive.com/oauth/authorize 与 openapi.alipan.com/oauth/。
  - 123云盘：open-api.123pan.com/api/v1/oauth2/access_token 与 yun.123pan.com/auth。
  - 移动云盘：miniapp.yun.139.com/open-mpplatform/oauth2/accessToken1。
  - 天翼云盘：api.cloud.189.cn/open/loginUrl.action 与 ctyun.huan.tv。

## 4. 网络与 API 契约
- **自建中心化服务端**：依托 okaapps.com 域名矩阵（vh.api.okaapps.com、vh.config.okaapps.com、vh.verify.okaapps.com、vh.image.okaapps.com），下发应用配置、授权验证、TMDB 聚合代理缓存（/api/v2/tmdb/）以及全平台服务授时（/api/v1/server-time）。
- **三方聚合与字幕契约**：集成 SubHD 爬虫解析（subhd.me、subhd.one）、Assrt 射手网查询（api.assrt.net/v1/sub/search）、OpenSubtitles v1 接口（api.opensubtitles.com/api/v1/subtitles），以及 Trakt 进度上报（api.trakt.tv）。
- **百度 PCS 与分片流拉取**：直连百度云加速下载节点（bd-ct20.baidupcs.com、xad0.baidupcs.com）与 pan.baidu.com/rest/2.0/xpan/multimedia，获取流媒体直链与分段数据。

## 5. 对自研的参考价值
- **完备的网盘限频器（QPSFactory）架构**：针对国内各家网盘严格的并发和频率限制，VidHub 为每个云盘量身定制了 QPSFactory（如 AliYunQPSFactory、Drive115QPSFactory、Yun139QPSFactory），在客户端层平滑请求削峰，彻底避免 429 报错或封号。
- **模块化 FileProvider 设计模式**：从 CloudFileProvider 派生各个具体实现，把 OAuth 授权、令牌刷新、目录分页、文件详情与媒体直链拉取标准化，使媒体库索引引擎能以完全一致的方式遍历不同网盘。
- **自建反代与凭据中转服务**：通过自建业务网关处理 115、华为等网盘复杂的授权回调与 TMDB 代理缓存，既保障了敏感密钥安全，又规避了客户端直接访问第三方服务的不稳定性。
