## 1. 技术栈、播放内核、体积、扩展

- **语言/架构**：Objective-C + Swift 混编，重度 RxSwift（`RxSwift/RxCocoa/RxRelay/RxBlocking/RxDataSources/RxCombine`）+ MVVM；依赖注入 Swinject；网络 Moya + Alamofire；WebSocket Starscream；Protobuf（gRPC 风格）。
- **存储**：**WCDB + sqlcipher**（本地库加密）；`zipzap` 处理 zip；`MMSecurity.framework`（192 KB，自家安全组件，Token/本地校验）。
- **音视频**：`TXFFmpeg` + `TXSoundTouch`（腾讯点播裁剪/变速）；**Agora RTC 全家桶**（`AgoraRtcKit` + 11 个 Extension，含 AI 降噪/美颜/人脸检测）→ 自习室/同桌/语音房；`liteav.sdk.qcloud.com`。
- **"播放内核"定位**：本 App 不是媒体播放器，音频能力服务于单词发音与例句朗读（`AgoraRtcMediaPlayer` 亦被复用为本地播放器）。`has.ffmpeg=true, mpv=false, libass=false`。
- **三方**：Sentry 崩溃、SwiftyBeaver 日志、极光推送 JPush、Lottie、SDWebImage、ZLPhotoBrowser、MJRefresh。
- **扩展**：2 个 —— `ShareExtension`、`momo_ios_widgetExtension`。
- **包内容**：1211 文件 / 103 个 `.strings` / 40 个 lproj（覆盖极广，含 `ko-KP`、`gre` 等异常 locale）。
- **StoreKit**：StoreKit 2 存在 —— `StoreKit.Transaction.Transactions.AsyncIterator.next()` + `StoreKit.VerificationResult`（= `Transaction.updates` 监听），同时保留 `SKPaymentTransactionObserver` 兼容层。

### 1.1 一处必须纠正的既有结论：**没有 Adapty**
`sdkscan.json` 把本包标成 `Adapty + IAPHelper`。经复核，**Adapty 是误报**：
- 全包 `grep -rila adapty Payload/` 只命中主二进制的 `__swift5` 段；
- `nm -a momo_ios | grep -i adapty` = **0**；
- 命中的原始字节是 Swift 符号名 `backgroundAdaptyQrSo7UIColorCF`，其中 `5Adapt` 是 Swift mangling 的**长度前缀标识符 "Adapt"**（5 字符），后面 `yQrSo7UIColorC F` 是类型编码 —— 与 Adapty SDK 无关（见 `python3` 读 offset 95265500 的原始字节）。
- 包内 `Frameworks/` 无任何 Adapty/RevenueCat 框架，二进制无 `app.adapty.io`、`AdaptyProfile`、`AdaptyUI` 任一字符串。

## 2. 付费墙与额度判定链

### 2.1 商品 ID
客户端硬编码两个 StoreKit 商品（紧邻 `MMK_PendingReceipts` / `MMK_CompletedReceipts` / `iap_uid` / `product_id` / `verify`）：

- **`com.maimemo.ios.momo.product.RC1`**
- **`com.maimemo.ios.momo.product.RC2`**
- 另有前缀常量 `com.maimemo.ios.momo.product.`（用于拼装/沙盒变体）与 `iap_sandbox_purchase`

> 注意：`com.maimemo.ios.momo.word.limit`、`.selected.words`、`.calendar.update` 三个**不是商品 ID**，而是 NSNotification/EventBus 事件名（它们与 `MMK_PrivacyCheckVersion`、`MMK_CloudCredential` 等默认键同段排列）。商品在服务端另有 `/v1/payment/products/`、`/v1/payment/products/coin` 下发（含"墨墨币"充值档）。

## 4. 可解锁分级

### 结论：**C 级**

**证据**
1. **唯一的额度数字来自服务端**：`getAvailableWordLimitWithCompletionHandler:` 的语义是"向服务端要可用上限"，字段 `inf_paid_words_num` 只出现在用户信息解码路径；本地无该值的持久化布尔/计数（本地只有加密 WCDB 与回执队列）。
2. **购买闭环强制服务端**：`verifyReceipt:productId:productName:transaction:prompt:` → `/v1/payment/iap/orders`，服务端回 `IAPVerifyResponseOrder`。无服务端确认，`inf_paid_words_num` 不会变。
3. **写词/扩词受服务端同步约束**：`/v1/sync/op`、`/v1/study/debts/*`、`DEBT_*` / `EXCEED_DEBT_LIM` 错误码说明"多背超限"是服务端记账；即使本地库改大，下次同步会被服务端覆盖或直接拒绝。
4. **本地库加密**：WCDB + sqlcipher，`MMSecurity` 管密钥派生；纯文本改库不可行。
5. **无客户端硬编码的权利表**：无 `isVip`/`isPro` 之类本地布尔（选择器表里只有 `isPurchasesLimited`、`privilegeState` 这类"服务端结果镜像"）。

**残留可动点（不足以升级到 B）**
- `MMK_CompletedReceipts` 本地回执缓存：可伪造"已完成"让 UI 少弹一次购买窗，但下一次 `/v3/users/me/privileges` 回来后即被打回。
- `_TtC8momo_ios12IAPTestGroup` / `iap_sandbox_purchase` / `screenRecordIAP`：存在 IAP 实验分组与沙盒标记，属 A/B 实验通道，不是绕过通道（未见本地开关把它变成"免费解锁"）。

## 5. 务实落点

### 5.1 Loon（拦截 `apis.maimemo.com`）
可尝试但收益有限：
- 改写 `/v3/users/me/privileges` 与用户信息响应里的 `inf_paid_words_num`（调大）→ **只能让"当前可用上限"这个数字变大**，实际加词时 `/v1/sync/op` 或学习接口会按服务端记账拒绝，表现为"数字对、加词失败"。
- 商品/价格接口（`/v1/payment/products/*`）改写无意义（价格由 StoreKit 弹窗决定）。

### 5.2 本地补丁
- Hook 选词超限判定（`promptWordLimitWithVocIds:canAddPartial:scene:onPurchase:onAdd:` 的调用方）与 `getAvailableWordLimitWithCompletionHandler:` 回调，可以做出"看起来能选超限词"的体验。
- 但词一旦进学习队列，`/v1/sync/op` 上行即被服务端按 `inf_paid_words_num` 校验（`EXCEED_DEBT_LIM` / 欠款逻辑），**会进入"欠款(debts)"状态而不是解锁**。这是产品设计上的强约束。

### 5.3 真正卡在服务端的（直说）
- **单词上限是账号属性**，不是客户端权益：买多少存在 `inf_paid_words_num`，服务端在学习同步/欠款结算时强制。
- **补签卡、例句发音订阅**同理（订阅到期日由服务端算）。
- 结论：本包**不适合** Loon 解锁；要做只能做"体验层伪装"，且会被同步打回。
