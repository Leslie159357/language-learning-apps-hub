## 4. 可解锁分级

### 结论：**B 级**（本地功能位可改，但有两道反篡改 + AI 额度服务端）

**支持可解（B 而非 C）的证据**
1. `isVip` / `vipAvailable` / `vipExpireDate` 是客户端自有属性（`T@"NSDate",N,R` 只读属性 + `IAPService` 单例），UI 与功能锁读的是它们，不是每次实时问服务端。
2. 本地键 `pollykannVipState` + `vipStartTimestamp/vipEndTimestamp` + `plk_proTrialDays` 构成完整的"本地会员态"。
3. Pro 权益是**功能开关**（下载/导出/YouTube/去广告/跟读录音），这些能力本体在客户端（mpv/ffmpeg 全在包内，`Libmpv`+`Libass` 可离线播放），不需要服务端发内容。
4. 存在 `DebugViewController` 与 `proDebug->D1 is valid until` 这类**本地 Pro 覆盖**实现痕迹 → 说明客户端本身就有"不依赖购买"的 Pro 置位路径。

**削弱项（为什么不是纯 A）**
1. `verifyFilterValue:withImprintMD5Value:withUserdefaultMD5Vlaue:` —— 对 `NSUserDefaults` 做 MD5 印记比对，**直接对抗"改偏好键"**；改键后印记不匹配会触发重置/失效（具体动作未定位，属风险项）。
2. `verifySysTimeWithCompletion:` / `deviceTimeVerify` / `verifyTimeInterval` —— 抗系统时间回拨，"改时间续会员"不可行。
3. `vipTicket` + `vipTicket verify failed`：账户响应里带凭证，验不过则整份账号数据判为无效。**凭证的具体校验算法未能定位**（Ghidra 未跑通），因此"Loon 直接改账户 JSON 能否通过"= **未定论**，按最坏情况按 B− 处理。
4. AI 字幕（`aiSubtitleDuration`）、AI 提问（`aiQuestionTimes`）、积分（`pointsBalance`）是服务端余额，且 `/vip/applePayAfterPayment` 后才入账。

## 5. 务实落点

### 5.1 Loon 落点（风险明确）
- **首选**：`api.pollykann.com` 的 `/vip/productList`（只影响商品展示，无解锁价值）
- **有价值但高风险**：账户响应（`PlkAccountInfo`）里的 `vipAvailable` / `proAvailable` → true、`vipExpireDate` → 远期。**但**该响应可能加密/签名（`needDecryptResponse`、`strictSignatureVerify:`），且带 `vipTicket`；纯 JSON 改写大概率触发 `vipTicket verify failed` → 账号被判无效（比不改更糟：可能导致登录态被判脏）。
- **折中**：只改 `/vip/productList` 与 H5 网关域名，不动账户接口；真正解锁交给本地补丁。

### 5.2 本地补丁落点（本包最优路径）
- Hook `_TtC9Pollykann10IAPService` 的 `isVip` / `vipAvailable` getter → true；或 hook `checkIsVipMemberWith:` / `vipFeaturesLockDetection` 直接返回放行。
- 注意必须同时绕过 `verifyFilterValue:withImprintMD5Value:withUserdefaultMD5Vlaue:`（否则改 `pollykannVipState` 会被印记校验发现）与 `verifySysTimeWithCompletion:`（否则改时间线被识别）。**Hook getter 而不改键**是更稳的绕法（不改存储 → 印记不变）。
- 若要走"资源购买联动"路径：`播放已购买资源自动解锁Pro功能` 说明存在"本地已购资源表 → Pro 置位"，可在资源表里塞一条已购记录（未验证可行性）。

### 5.3 真正卡在服务端的（直说）
- **AI 字幕生成 / AI 提问**：`aiSubtitleDuration`、`aiQuestionTimes` 服务端扣减，任务提交到 `video.pollykann.com/upload` + `/subtitle-auto-matching/*`，本地改数字不会让服务端多算一秒。
- **积分充值**：`pointsBalance` 只能靠服务端入账。
- **多设备登录上限**：`/device/veryDevice` 服务端风控。
- 但**核心播放能力不卡服务端**：mpv/ffmpeg/libass 全在包内，本地/网盘/直链内容离线可播 —— 这是它能做到 B 级的结构性原因。
