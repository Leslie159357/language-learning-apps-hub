# LinguoLand 英文原著查词 深度架构分析报告

## 一、 技术栈判定

根据 `app_graph.yaml`、`recon/source_files.txt` 与原生符号证据判定，LinguoLand（Bundle ID: `com.linguoland.app`，版本 2.3.0，最低系统要求 iOS 15.1）是一款典型的**现代 React Native + Expo 跨平台架构**应用，由 Hermes JavaScript 引擎驱动，辅以定制化的 Swift 原生能力模块。

- **语言与架构选型**：宿主二进制以 Swift / Objective-C 充当壳工程与原生扩展，实际的 UI 交互、原著排版阅读器、查词逻辑与复习卡片均由运行在 Hermes VM 上的 React Native / TypeScript 驱动。
- **动态库与引擎支撑**（证据来源于 `app_graph.yaml` 的 `frameworks`）：
  - `Payload/LinguoLand.app/Frameworks/React.framework`（React Native 核心框架）
  - `Payload/LinguoLand.app/Frameworks/ReactNativeDependencies.framework`（包含 folly、boost、glog 等底层基础设施）
  - `Payload/LinguoLand.app/Frameworks/hermesvm.framework`（Facebook Hermes 高性能 JavaScript 虚拟机）
- **播放与音视频内核**：依赖系统级 `AVFoundation`（`AVPlayer`、`AVQueuePlayer`、`AVAudioRecorder`），并通过 Expo 原生桥接层 `AudioModule.swift`、`AudioPlayer.swift` 与 `AudioRecorder.swift` 将音频播放与录音控制暴露给前端。
- **依赖 SDK 与模块**：
  - Expo 现代模块核心：`expo-modules-core`（`EXNativeModulesProxy.m`、`EXModuleRegistry.m`）、`EXConstants.bundle`、`EXUpdates.bundle`。
  - 核心生态库：`react-native-screens`（原生页面导航管理）、`react-native-gesture-handler`（多手势引擎）、`async-storage`（`RNCAsyncStorage.m`）。
  - 内购服务：OpenIAP（`kit.openiap.dev`，对应类 `OpenIapStore`、`ExpoIapModule`）。
- **规模证据**：主二进制 `LinguoLand` 为 12.57 MB，包内包含 4 个动态 Framework 库，文件总数 246 个。

## 二、 模块分层

基于 `recon/all_classes.txt` 与 `source_files.txt` 归纳，原生层主要承担运行环境支撑与硬件级功能桥接：

1. **启动与导航层**：负责 React Native 容器初始化、Expo 生命周期分发与原生导航栈管理。
   - 真实类名：`ExpoAppDelegate`、`ExpoAppDelegateSubscriberManager`、`ExpoReactNativeFactory`、`DevLauncherAppController`、`RNSScreen`、`RNSScreenStack`、`RNSTabBarAppearanceCoordinator`、`RNSModule`。
2. **业务服务模块层（Expo Native Modules）**：提供硬件按键拦截、原声朗读、本地 OCR 等关键业务服务。
   - 真实类名：`AudioModule`、`AudioRecorder`、`LocalOcrModule`、`SpeechModule`、`VolumeKeyPagingModule`、`ReaderFontsModule`、`SharingModule`、`DocumentPickerModule`、`ImageManipulatorModule`。
3. **数据持久与存储层**：管理 SQLite 数据库、加密安全密钥与离线键值存储。
   - 真实类名：`SQLiteModule`、`RNCAsyncStorage`、`SecureStoreModule`、`ExpoSecureStore`、`FileSystemModule`、`FileSystemLegacyModule`、`UpdatesLogReader`。
4. **网络与更新分发层**：负责底层网络传输、热更新资源拉取与内购二次验证。
   - 真实类名：`ExpoFetchModule`、`NetworkingHelpers`、`NativeResponse`、`OpenIapStore`、`ServerRegistrationModule`、`EASClientModule`。
5. **UI 与视图容器层**：管理 React Native 与原生视图的桥接混编、Web 渲染及图像加载。
   - 真实类名：`AnyExpoSwiftUIHostingView`、`AnyExpoView`、`DomWebView`、`DomWebViewModule`、`ExpoFabricView`、`RNSReactBaseView`、`BlurhashLoader`、`ImageView`、`ReloadScreenView`。

## 三、 能力模块归纳

从逆向类名表中提炼的核心业务能力及对应原生支撑组件：

- **播放**：提供双耳原声听书与长音频后台回放，支持播放队列。
  - 命中类名：`AVPlayer`、`AVQueuePlayer`、`AudioPlayer`、`AudioPlaylist`、`AudioModule`、`Convertibles+CMTime`。
- **字幕与原著渲染**：通过原生 Web 容器与离线排版结合实现图文混排。
  - 命中类名：`DomWebViewModule`、`DomWebView`、`ExpoWKPDFRenderer`、`ExpoWKViewPrintPDFRenderer`。
- **跟读录音**：提供发音录制与音频权限请求。
  - 命中类名：`AVAudioRecorder`、`AudioRecorder`、`AudioRecordingRequester`、`AudioRecordingException`、`AVSpeechSynthesizer`。
- **词汇与原著查词**：
  - **离线图像取词**：`LocalOcrModule`（利用系统 Vision/CoreML 离线提取小说插图或屏幕生词）。
  - **按键翻页**：`VolumeKeyPagingModule`（拦截硬件音量增减键实现免触屏电子书快速翻页）。
  - **多字体呈现**：`ReaderFontsModule`、`FontLoaderModule`（动态挂载多样化英文原著排版排数字体）。
- **复习算法**：上层复习调度算法位于 Hermes JS 字节码中，底层依靠原生 `SQLiteModule` 与 `RNCAsyncStorage` 提供低延迟的词库读写支持。
- **AI / ASR / TTS**：
  - 语音朗读：`SpeechModule`、`ExpoSpeechUtterance`、`AVSpeechSynthesizer`、`AVSpeechUtterance`。
  - 本地未挂载重型 ASR 模型，侧重于轻量化系统原生 TTS 驱动。
- **导入导出**：支持第三方原著 EPUB/TXT 文件选择与打印生成。
  - 命中类名：`DocumentPickerModule`、`DocumentPickingDelegate`、`UIDocumentPickerViewController`、`ExpoPrintModule`、`ExpoPrintToFile`、`FileSystemModule`。
- **账号与权益同步**：基于 OpenIAP 协议的内购订阅验证。
  - 命中类名：`ExpoIapModule`、`ExpoIapOnsideModule`、`OpenIapStore`、`OpenIapVersion`、`EASClientModule`、`UpdatesModule`。

## 五、 源文件拓扑与工程线索

根据 `recon/source_files.txt` 中提取的 145 条应用源文件与 47 条内嵌库源文件分析：

- **典型 Expo Modules 模块化工程**：作者遵循 Expo 现代原生模块规范，将原生特异性能力拆分为独立模块文件（例如 `LocalOcrModule.swift`、`VolumeKeyPagingModule.swift`、`ReaderFontsModule.swift`），并通过 `ModuleDefinition.swift` DSL 将属性、事件与异步方法清晰暴露。
- **跨平台依赖管理**：通过 CocoaPods 接入前端依赖，明确分出 `/node_modules/@react-native-async-storage/`、`/node_modules/expo-modules-core/` 与 `/node_modules/react-native-screens/` 等标准路径。
- **单 Target 架构 + 动态库桥接**：主 Target 为 `LinguoLand`，外挂 React、Hermes 等 4 个动态 Framework，未对原生代码进一步划分独立 Framework Target，整体编译链由 React Native CLI + Xcode 构建。

## 六、 对自研的参考价值

### 1. 值得借鉴的设计
- **按键翻页与离线 OCR 模块化设计**：`VolumeKeyPagingModule.swift`（监听系统物理音量按键改变并转化为阅读器翻页动作）与 `LocalOcrModule.swift`（结合 iOS 视觉能力进行拍照划词），封装非常紧凑，非常适合直接移植进自研的原著阅读器。
- **字体动态载入方案**：`ReaderFontsModule.swift` 提供了动态注册字体文件的标准通道，使得语言学习软件能快速提供诸如 Serif、Dyslexic 等适配阅读障碍和外语排版的专属字体。
- **Swift DSL 封装桥接**：采用现代 Expo Modules API（基于 Swift 泛型与闭包），比起老旧的 ObjC `RCT_EXPORT_MODULE` 宏具有更强的类型安全性和更低的出错率。

### 2. 历史包袱与不宜照搬
- **过度跨平台带来的体积膨胀**：为了提供简单的查词与电子书阅读，引入了完整的 React Native、Hermes 运行时及 4 个动态库，导致安装包基础体积激增（12.57 MB 主二进制加上十余兆框架），性价比不如纯 Swift 原生。
- **微秒级音画同步受限**：JS 桥接层在处理复杂的精听波形渲染、句子 A-B 循环与高速字幕滚轮时，不可避免存在线程上下文切换延迟，对于追求极限听力跟读体验的应用而言，核心播放链条应当纯原生化。
