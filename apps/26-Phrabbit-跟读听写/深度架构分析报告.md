# 深度架构分析报告：26-Phrabbit-跟读听写

本报告基于脱壳 Mach-O 二进制符号提取、编译期源文件拓扑（`#file`）、URL 与域名契约提取及 REA 6.8.0 Application Graph 静态反编译事实生成，覆盖应用 `com.chichipoposan.phrabbit`（v4.0.0，最低支持 iOS 18.0）。

## 一、技术栈与播放内核

- **客户端架构**：纯原生 Swift / SwiftUI 现代架构（目标版本 iOS 18.0+），无 React Native 或 Flutter 跨平台混合壳。
- **播放内核**：基于苹果原生 `AVFoundation` 体系（`AVPlayer`、`AVPlayerItem`、`AVPlayerLayer`、`AVAudioPlayer`、`AVAudioEngine`）。集成了系统级画中画能力（`AVPictureInPicturePlayerLayerView`）；针对外部流媒体，通过 `YouTubePlayerController` 与 `YouTubePlayerWebView`（加载 `https://www.youtube.com/iframe_api`）实现 YouTube 视频的桥接播放。
- **内嵌模型与推理引擎**：深度集成 Hugging Face 官方 `swift-transformers` 运行时（包内固化 `swift-transformers_Hub.bundle`，联网寻址 `https://huggingface.co`）。构建了先进的本地离线语音识别矩阵：
  - `WhisperSpeechEngine`：在端侧直接运行 OpenAI Whisper 语音模型。
  - `FoundationModelsEngine`：利用 iOS 18+ 原生 Apple Intelligence Foundation Models 框架进行系统级推理。
  - `LegacySpeechEngine` 与 `SFSpeechRecognitionResult`：作为兼容降级与标准原生 ASR 通道。

## 二、模块分层

根据 474 个原生类与 140 条核心编译期源码路径，应用划分为以下高内聚层次：

1. **表现层（View / UI）**：
   - 播放与学习面板：`PlayerView`、`StreamPlayerView`、`VideoPlayerView`、`ShadowingView`、`AudioArtworkView`。
   - 听写互动组件：`DictationAttemptRow`、`DictationAnswerEntryView`、`CaptionCardVisibility`。
2. **状态中枢与路由层（ViewModel / Orchestration）**：
   - 状态控制器：`PlayerViewModel`、`PlayerStateManager`、`PlayerWebBridge`。
   - 会话与路由：`VideoRouter`、`VideoSession`。
3. **播放控制与分流执行层（Playback & Transport）**：
   - 音频与视频服务：`AudioService`、`AudioProcessor`、`VideoPlayerController`、`YouTubePlayerController`。
   - 业务播放器特化：`AudioDictationPlayer`、`StreamDictationPlayer`、`VideoDictationPlayer`、`AudioPracticeTransport`。
4. **语音分析与端侧 AI 层（Speech & AI Engine）**：
   - 核心推理引擎：`WhisperSpeechEngine`、`FoundationModelsEngine`、`LegacySpeechEngine`、`AnalyzerSpeechEngine`、`DictationSpeechEngine`。
   - 音频切片与流式识别：`VADAudioChunker`（端侧静音检测分块）、`AudioRangeSTTService`、`STTService`、`STTAudioReader`、`STTRecoverySession`、`AudioStreamTranscriber`、`AudioEncoder`。
5. **字幕、翻译与本地素材层（Captions, Translation & Storage）**：
   - 翻译中枢：`AppleTranscriptTranslator`、`AITranslationEngine`、`AITranslationService`、`TranscriptTranslationService`。
   - 数据实体与结构：`ArtworkStore`、`AudioFile`、`VideoItem`、`VideoCue`、`VideoBookmark`、`DictationSession`、`DictationAttempt`、`ShadowingSession`、`ShadowingTake`。

## 三、能力模块

- **影子跟读（Shadowing）**：
  - 设计了统一的数据源抽象：`LocalFileShadowingSource`（本地文件）、`StreamShadowingSource`（流媒体）、`VideoShadowingSource`（视频），由 `ShadowingSession` 和 `ShadowingTake` 追踪单句练习状态与多次录音取样。
- **A-B 复读与区间转录**：
  - 基于 `VideoCue` 和 `VideoBookmark` 锚定时间戳，核心调度类 `AudioRangeSTTService` 与 `VideoRangeSTT` 支持对特定 A-B 区间实施即时切片并调用端侧 STT 重转录。
- **听写（Dictation）**：
  - 核心由 `DictationSession`、`DictationAttempt` 维护听写进度，配合专用播放器 `AudioDictationPlayer`、`StreamDictationPlayer`、`VideoDictationPlayer` 实施“单句播放-暂停-输入比对-重听”，由 `DictationSpeechEngine` 提供精准匹配验证。
- **字幕管理与翻译**：
  - 支持视频与流媒体多语言字幕同步（`VideoCaptionTranslation`、`StreamCaptionTranslation`），并接入 iOS 系统级翻译与大模型翻译桥接（`AppleTranscriptTranslator`、`AITranslationEngine`）。
- **本地素材库与多源管理**：
  - `ArtworkStore` 管理专辑封面与本地素材缓存；支持本地音频导入播放与在线 YouTube 视频无缝嵌入跟读。
- **端侧 AI 架构**：
  - 具备业内领先的本地语音处理能力：前端通过 `VADAudioChunker` 自动按停顿分句，后端可在 `WhisperSpeechEngine` 与 `FoundationModelsEngine` 间灵活切换，识别全过程不经过外部私有服务器。

## 四、网络与 API 契约

- **自有域名与接口**：
  - 静态提取包含自有域名 `phrabbit.net`，以及官方使用说明站点 `https://ki3240.github.io/phrabbit-guide/`。
  - 提取结果中**无自有业务 REST 接口路径**。
- **服务契约本质**：
  - 本应用采用完全的 **Local-First（本地优先/零后端）** 架构。所有音视频切片、Whisper 语音转写、听写打分比对、字幕生成均在用户设备端完成。
- **第三方与外部依赖**：
  - **广告变现**：集成 Google AdMob（`GoogleMobileAds.framework`、`admob-gmats.uc.r.appspot.com`、`pagead2.googlesyndication.com`）。
  - **开放模型与内容**：模型权重拉取对接 `https://huggingface.co`；外链视频播放对接 `https://www.youtube.com/iframe_api`。

## 五、对自研的参考价值

1. **多引擎端侧 ASR 矩阵范式**：Phrabbit 提供了业界典范的端侧语音引擎架构——通过抽象类统一管理 `WhisperSpeechEngine`、`FoundationModelsEngine` 与 `LegacySpeechEngine`，既能在 iOS 18 高端设备上榨干系统 NPU 性能，又能利用 Whisper 保证转录准确率，完全摆脱对高成本云端 ASR 的依赖。
2. **VAD 静音分块与区间转录管线**：其 `VADAudioChunker` + `AudioRangeSTTService` 配合 `VideoCue` 的设计，完美解决了长音频/视频无法直接高精度跟读的痛点，将任意音视频转化为自动切片的跟读素材。
3. **多模态播放器适配层架构**：将音频、网络流、视频乃至 YouTube 统合在统一的 `*DictationPlayer` 与 `*ShadowingSource` 接口之下，使跟读与听写核心业务逻辑完全解耦于具体播放载体。
