# 深度架构分析报告：25-Hanas-英语影子跟读

本报告基于脱壳 Mach-O 二进制符号提取、编译期源文件拓扑（`#file`）、URL 与域名契约提取及 REA 6.8.0 Application Graph 静态反编译事实生成，覆盖应用 `tokyo.hanas.shadowing.ios`（v2.4.3）。

## 一、技术栈与播放内核

- **客户端架构**：基于 React Native + Expo 框架开发，采用 React Native Fabric 新架构（包含 `ExpoFabricView`、`RCTModuleProviders.m`、`react-native-screens`、`react-native-svg`、`react-native-gesture-handler`）。原生层通过 Expo 模块化规范桥接（`ExpoAppDelegate`、`ExpoReactNativeFactory`、`EXConstants.bundle`）。
- **播放内核**：未集成 mpv 或 ffmpeg。底层完全依赖苹果原生 `AVFoundation` 框架（`AVPlayer`、`AVPlayerItem`、`AVPlayerItemTrack`、`AVAudioEngine`）。原生层封装了播放控制与视图管理类 `VideoPlayer`、`VideoPlayerObserver`、`VideoManager`、`AudioPlayer`，并通过 `OrientationAVPlayerViewController` 和 `VideoView` 挂载视频渲染与横竖屏旋转。
- **内嵌模型**：无内嵌离线模型（未打包 Whisper、CoreML 模型包或 ONNX Runtime）。语音识别与合成完全依赖 iOS 系统级能力，通过 `ExpoSpeechRecognitionModule` 与 `ExpoSpeechRecognizer` 桥接苹果原生 `SFSpeechRecognizer`，发音朗读依赖系统 `AVSpeechSynthesizer` 与 `AVSpeechUtterance`。

## 二、模块分层

根据 954 个原生类与 251 条编译期源码路径，应用可划分为以下四个静态层次：

1. **表现层（UI / Screens）**：
   - 视图容器与组件：`OrientationAVPlayerViewController`、`VideoView`、`VideoAirPlayButtonView`、`RNSBottomTabsHostComponentView`、`RNSScreenStack`。
   - 交互与通知：`ExpoNotificationPresenter`、`HanasLiveActivity`（iOS 灵动岛与锁屏实时活动组件）。
2. **核心业务与媒体引擎层（Business / Media Core）**：
   - 媒体调度：`VideoPlayer`、`VideoPlayerObserver`、`VideoManager`、`VideoSourceLoader`、`WeakPlayerObserverDelegate`。
   - 轨道与字幕管理：`VideoPlayerSubtitles`、`VideoPlayerAudioTracks`、`VideoItem`。
   - 音频采集与播放：`AudioPlayer`、`AudioModule`、`AudioRecorder`、`AudioRecordingRequester`、`RecordingDelegate`。
3. **原生桥接与能力抽象层（Bridge & Native Modules）**：
   - 语音服务桥接：`ExpoSpeechRecognitionModule`、`ExpoSpeechRecognizer`、`SpeechModule`、`EXSpeechRecognitionPermissionRequester`。
   - 系统基础桥接：`ExpoFetchModule`、`ExpoHeadModule`、`AssetModule`、`EXPermissionsService`。
4. **数据存储、凭证与商业化层（Data / Storage & Commerce）**：
   - 文件与缓存：`VideoCacheManager`、`DefaultFontFileManager`、`FileDownloader`、`FontDownloadSession`、`PhotoLibraryAssetLoader`。
   - 订阅与权益：集成 RevenueCat SDK（`PurchasesOrchestrator`、`CustomerAPI`、`LocalReceiptFetcher`、`GetProductEntitlementMappingOperation`、`CachingTrialOrIntroPriceEligibilityChecker`）。

## 三、能力模块

- **跟读与录音评分**：
  - 由 `AudioRecorder`、`AVAudioRecorder`、`AVAudioEngine` 和 `AudioRecordingRequester` 实现音频采集，捕获跟读音频。
  - 评分与语音校验基于 `ExpoSpeechRecognizer` 调起 iOS 系统的 `SFSpeechRecognizer` 实现流式/分段文字识别，无私有神经网络评分权重包。
- **A-B 复读与播放控制**：
  - 依赖 `VideoPlayer` 与 `VideoPlayerObserver` 监听 `AVPlayerItem` 的播放时间戳（通过 `AVPlayerItemTrack` 与状态监听），在 UI 触发时间区间循环。
- **听写**：
  - 静态符号中未发现独立听写打分字典引擎，依托 `StringDictionary`、`NSMutableDictionary` 及 JS 业务层完成字词拼写核对。
- **字幕管理与渲染**：
  - 原生层维护 `VideoPlayerSubtitles` 结构，负责解析并对齐字幕时间轴，通过 `VideoPlayerObserver` 与视频帧推进保持同步，前端通过 React Native 视图层渲染字幕文本。
- **本地素材库与资源管理**：
  - 本地与网络资源缓存依托 `VideoCacheManager` 与 `VideoSourceLoader`，媒体文件下载调度通过 `FileDownloader` 及 `NSURLSessionDownloadTask` 处理；支持系统相册资源载入（`PHPhotoLibrary`、`PhotoLibraryAssetLoader`）。
- **AI 能力**：
  - 无自研云端 LLM 接口或本地大模型，仅依托系统原生 `SFSpeechRecognizer` 实现 ASR，`AVSpeechSynthesizer` 提供标准发音朗读。

## 四、网络与 API 契约

- **自有域名与接口**：
  - 提取到自有域名：`tokyo.hanas.shadowing.io`、`7.tokyo.hanas.shadowing.io`。
  - 提取结果中**无自有业务 REST/GraphQL 接口路径**，业务核心逻辑与教学数据大多静态固化在前端打包产物中或直接走云端 BaaS。
- **第三方与云端 BaaS 服务契约**：
  - **订阅权益中枢**：高度依赖 RevenueCat 体系，包含 `api.revenuecat.com`、`api-paywalls.revenuecat.com`、`api-diagnostics.revenuecat.com`，负责内购校验与动态付费墙。
  - **用户认证与安全**：依赖 Google Sign-In（`oauth2.googleapis.com`、`www.googleapis.com`）与 Firebase App Check（`firebaseappcheck.googleapis.com`、`firebaseinstallations.googleapis.com`）。
  - **网络特性**：属于典型的“前端应用 + 第三方 BaaS + 无自建业务 API 网关”架构。

## 五、对自研的参考价值

1. **跨平台影子跟读方案的可行性参考**：证明了基于 React Native / Expo 结合原生 `AVPlayer` 与 `SFSpeechRecognizer` 可以完整支撑包含视频跟读、实时活动（LiveActivity）的商业级应用，无需从零用纯原生重构 UI。
2. **轻量化字幕与轨道抽象设计**：原生模块中将 `VideoPlayerSubtitles` 与 `VideoPlayerAudioTracks` 抽离为与播放器绑定的实体，通过观察者模式（`VideoPlayerObserver`）向前端派发状态，逻辑清晰且开销极小。
3. **零自建后端成本模型**：通过充分借力 iOS 原生语音识别（免去云端 ASR 成本）与 RevenueCat（免去自建内购鉴权服务），实现极低运维成本的交付模式。自研系统若需初期降低云端推理与服务器预算，可直接借鉴此分工范式。
