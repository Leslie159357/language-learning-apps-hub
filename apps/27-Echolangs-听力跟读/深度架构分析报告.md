# 深度架构分析报告：27-Echolangs-听力跟读

本报告基于脱壳 Mach-O 二进制符号提取、编译期源文件拓扑（`#file`）、URL 与域名契约提取及 REA 6.8.0 Application Graph 静态反编译事实生成，覆盖应用 `com.echolangs.echoapp`（v3.2.2，最低支持 iOS 17.0）。

## 一、技术栈与播放内核

- **客户端架构**：纯原生 Swift / SwiftUI 极简架构。主二进制体积仅 3.15 MB，包内仅包含 29 个资源文件，0 个外部动态库（Framework），无任何第三方 UI 跨平台容器，属于典型的极致瘦客户端（Thin-Client）。
- **播放内核**：未引入 mpv、ffmpeg 等第三方 C/C++ 播放引擎，完全依托苹果原生 `AVFoundation`（`AVQueuePlayer`、`AVPlayerItem`、`AVAudioPlayer`）。应用核心通过 `EchoPlayerEngine` 调度，并自研了基于 `AVQueuePlayer` 的队列切片播放体系：`EchoTmttSequencePlayer`、`EchoTnetPlayer`、`TNETSharedPlayer`、`TNTPlaybackCoordinator`。
- **内嵌模型**：**完全无内嵌 AI / ML 模型**（未包含 Whisper、CoreML 权重包或 ONNX Runtime）。客户端不承担端侧大模型推理与语音声学识别，全部教学切片与对齐数据均由服务端预处理生成。

## 二、模块分层

根据 121 个原生类与 29 个核心 Swift 架构类型，应用呈现高度清晰的单体模块化分层：

1. **表现层（SwiftUI Views）**：
   - 核心页面：`HomeView`、`MyProfileView`、`ShadowAccountView`、`UpgradeProSheetView`。
   - 练习组件：`MicroDictationView`（微听写面板）、`WordBankDictationView`（词库听写卡片）、`HomeTodayCardView`、`DownloadTaskCardView`。
2. **播放编排与时序协调层（Playback Orchestration）**：
   - 调度核心：`EchoPlayerEngine`、`EchoPlaybackProgress`、`EchoAudioSessionManager`、`SleepTimerController`。
   - 序列播放实现：`EchoTmttSequencePlayer`、`EchoTnetPlayer`、`TNETSharedPlayer`、`TNTPlaybackCoordinator`。
3. **录音与听写交互层（Recording & Practice）**：
   - 音频采集：`EchoAudioRecorder`、`RecordingSession`。
   - 练习数据结构：`DictationAudio`、`DictationSession`。
4. **网络服务与同步层（Networking & Sync）**：
   - 通信网关：`EchoAPIClient`、`UserSyncService`、`HomeSectionsService`、`HomeModel`。
   - 用户鉴权：`ClerkAuthService`。
   - 商业化与系统：`StoreKitManager`、`DailyReminderRouter`、`EchoAppDelegate`。
5. **下载与持久化仓储层（Download & Repository）**：
   - 离线调度：`BackgroundDownloadSession`、`DownloadCoordinator`、`DownloadQueueManager`、`UnitDownloader`。
   - 本地数据：`TmttRepository`（TMTT 切片仓储）、`ProgressWriter`（学习进度写入器）。

## 三、能力模块

- **跟读能力（Shadowing）**：
  - 由 `EchoAudioRecorder` 负责麦克风录音会话建立与音频持久化，在 `RecordingSession` 中管理录音片段并与课程切片绑定，通过 `ShadowAccountView` 汇总跟读记录。
- **A-B 复读与 TMTT 序列重放**：
  - 不采用客户端动态波形切片方案，而是利用其自研的 TMTT/TNET 协议格式。由 `EchoTmttSequencePlayer` 基于 `AVQueuePlayer` 预先加载句子级音频切片序列，`TNTPlaybackCoordinator` 精准控制单句重放、区间循环或下一句衔接。
- **听写（Dictation）**：
  - 提供 `MicroDictationView` 与 `WordBankDictationView`，配合 `DictationAudio` 与 `DictationSession`。通过预置的单词库与服务端标注词性，引导用户在听取分句音频后进行单词重组或听写输入。
- **字幕与文稿渲染**：
  - 字幕数据结构由 `TmttRepository` 本地持久化维护，与 `EchoPlaybackProgress` 严格同步推进，避免端侧重度解析 SRT/VTT 文件的计算损耗。
- **本地素材库与后台下载**：
  - 拥有完整的模块化课程离线下载体系，通过 `UnitDownloader` 针对单元课程批量拉取，由 `DownloadQueueManager` 与 `BackgroundDownloadSession` 维持 iOS 后台断点下载。
- **AI 能力**：
  - 客户端零内置 AI 运算；翻译与切片生成依托云端后端大模型完成，客户端负责结构化消费。

## 四、网络与 API 契约

Echolangs 拥有本组应用中最规范、完整的自建后端 API 体系：

- **自有域名体系**：
  - 国内业务 API：`api-cn.echolangs.cn`
  - 国际/主业务 API：`richapi.echolangs.com`
  - 媒体与分段 CDN：`tnet.echolangs.cn`、`tnet.echolangs.com`
  - 认证网关：`clerk.echolangs.com`
  - 门户与文档：`echolangs.cn`、`echolangs.com`、`guide.echolangs.com`
- **明确接口 URL 契约**：
  - `https://api-cn.echolangs.cn/api/mobile`：国内移动端核心数据接口。
  - `https://richapi.echolangs.com/api/auth`：主认证与登录校验。
  - `https://richapi.echolangs.com/api/mobile`：主移动端数据与业务接口。
  - `https://richapi.echolangs.com/api/mobile/tnet/guest?action=get_trans_langs&locale=`：语言包与翻译列表拉取。
  - `https://tnet.echolangs.com/`：TNET 音频切片与课程包分发 CDN。
  - `https://clerk.echolangs.com/v1`：基于 Clerk 托管的用户身份认证中心。
- **网络契约特征**：
  - 实行了标准的“国内外双路由”策略（CN 与 Global 双活域名），认证层抽离给专用 Clerk 服务，静态媒体资源（TNET）与业务元数据 API 完全解耦。

## 五、对自研的参考价值

1. **“瘦客户端”架构的最优落地实践**：通过将复杂的音视频切片、ASR 对齐、字幕翻译全部放在云端流水线处理，并将结构化结果封装为专用 TMTT 资源包下发，使得 iOS 客户端仅需 3.15 MB 即可提供极度流畅、零发热的跟读听写体验。
2. **基于 AVQueuePlayer 的序列播放器设计**：`EchoTmttSequencePlayer` 与 `TNTPlaybackCoordinator` 巧妙复用苹果底层队列播放器机制，直接以切片切片无缝拼接的方式实现 A-B 复读与句子连播，避免了长音频频繁 seek 带来的卡顿与音频破音。
3. **高可用的云端一体化网络布局**：其清晰的国内外 API 隔离（`api-cn` vs `richapi`）、专用媒体分发域（`tnet`）以及第三方鉴权（`clerk`）的结构，为面向出海与多地域交付的语言学习产品提供了标准基准。
