## 1. 播放内核与底层渲染架构

### 1.1 核心播放引擎与解码管线
EplayerX 采用了基于开源多媒体框架 **KSPlayer** 深度二次开发的架构（类名前缀 `_TtC8KSPlayer...`），底层以 **FFmpeg 动态库全家桶** 为核心解复用与软解码基石：
- **FFmpeg 动态库矩阵**：
  - `Libavcodec.framework`：核心音视频编码解码。
  - `Libavformat.framework`：多协议网络拉流与容器解封装（MKV, MP4, TS, FLV 等）。
  - `Libavfilter.framework`：视频/音频滤镜处理。
  - `Libavutil.framework`, `Libswresample.framework`, `Libswscale.framework`, `Libavdevice.framework`。
- **新兴视频格式解码加速**：
  - `libdav1d.framework`：开源 AV1 视频软解引擎，专为移动端多线程优化。

### 1.2 硬解与 HDR / 视频渲染链路 (libplacebo + MoltenVK)
EplayerX 在渲染管线上采用了极具技术特色的现代图形渲染方案：
- **硬件解码加速**：通过 FFmpeg VideoToolbox 硬件加速模块调用 iOS 系统的 `VTDecompressionSession`，支持 H.264/HEVC/ProRes 硬解。
- **跨平台现代渲染核心**：
  - `MoltenVK.framework`：将 Vulkan 1.2+ API 指令实时转换为 Apple Metal 图元指令。
  - `libplacebo.framework`：基于 Vulkan (MoltenVK) 的专业级 GPU 图像后处理库，提供行业前沿的高保真色调映射（Tone Mapping）、Lanczos/EWA 重采样缩放、抖动（Dithering）处理。
  - `lcms2.framework` (Little CMS 2)：专业级 ICC 色彩管理引擎。
- **杜比视界 (Dolby Vision) 深度支持**：
  - `libdovi.framework`：杜比视界 RPU（Reference Processing Unit）元数据解析与重构库，提取 Profile 5 / Profile 7 / Profile 8 动态元数据。
  - 核心处理类：`_TtC8EplayerX21DoviThumbnailRenderer`、`MetalPlayView`、`MetalView`。
- **AVPlayer 降级与备用链路**：
  - 保留 `_TtC8KSPlayer14KSAVPlayerView` 与 `_TtC8KSPlayer10KSAVPlayer`，用于系统原生流媒体回退。

### 1.3 专业音频与全景声管线
- 引入三大专业音频解码与渲染动态库：
  - `TrueHD.framework`：Dolby TrueHD 无损环绕声解码。
  - `DTSX.framework`：DTS:X 与 DTS-HD Master Audio 多声道解码。
  - `ObjectAudio.framework`：Dolby Atmos（杜比全景声）空间音频对象定位与虚拟化渲染。
  - `libopus.framework`：Opus 高效音频格式解码。

### 1.4 字幕渲染引擎 (libass)
- **采用完整的 libass 字幕渲染管线**：
  - `libass.framework`：完整支持 ASS/SSA 复杂特效字幕排版、动画、图形绘制。
  - `libfreetype.framework` 与 `libfontconfig.framework`：字形栅格化与字体匹配系统。
  - `libfribidi.framework` 与 `libharfbuzz.framework`：双向文本（BiDi）处理与复杂文字排印塑形引擎。
  - `libzvbi.framework`：DVB 电视与 VBI 隐藏字幕解码。

### 1.5 扩展与技术栈
- **语言体系**：纯 Swift 5.9+ 构建，大量采用 Swift Concurrency (`async/await`, `CheckedContinuation`) 与 Combine 框架。
- **CarPlay 深度支持**：声明 `CPTemplateApplicationSceneSessionRoleApplication`，实现专属车载交互界面 `EplayerX.CarPlaySceneDelegate`。
- **智能弹幕防遮挡**：
  - 弹幕源：接入弹弹 play API（`DandanAPI`: `https://api.dandanplay.net`）。
  - 遮挡算法：`com.snowlee.eplayerx.danmaku-occlusion`，基于 CoreImage 原生形态学滤镜（`CIMorphologyMaximum`, `CIMinimumCompositing`）实时识别人物前景与轮廓，实现弹幕智能从人物身后穿过的效果。
- **AI 大模型字幕翻译**：
  - 集成阿里 DashScope（通义千问 `https://dashscope.aliyuncs.com/compatible-mode/v1`）、DeepSeek、Google Gemini，实现外挂字幕实时 AI 翻译。

## 2. Pro 判定链与商业化状态机

### 2.1 StoreKit 产品 ID 与权限标识符
EplayerX 采用第三方商业化聚合平台 **RevenueCat** 进行权限治理，全量提取出的产品与 Entitlement 如下：

| 标识符类型 | 标识名称 | 说明 |
| :--- | :--- | :--- |
| **Entitlement ID** (权限组) | `eplayerx_mac_pro` | 统领全功能 Pro 权益的核心权限标识符 |
| **In-App Product ID** (购买项) | `com.snowlee.eplayerx.Lifetime_2.99` | 终身买断许可 (EplayerX Pro Lifetime) |

### 2.2 Pro 判定核心类、类型与方法
1. **统一门禁服务类**：
   - 类名：`_TtC8EplayerX22NativePurchasesService`
   - 内部架构：直接包装 `RevenueCat.Purchases` 客户端实例。
2. **状态与枚举**：
   - 权限属性：`NativePurchasesService.isPro` (Bool)
   - 订阅方案枚举：`NativePurchasesService.currentPlan` (`CurrentPlan` enum)
   - 状态更新代理：遵守 `RCPurchasesDelegate` 协议，通过 `purchases(_:receivedUpdated:)` 接收最新的 `CustomerInfo`。
3. **门禁保护功能点**：
   - 高清/全景声硬解直通与特定 HDR 色彩映射。
   - AI 大模型字幕翻译调用（DashScope / DeepSeek / Gemini）。
   - 智能弹幕防遮挡渲染（`danmaku-occlusion`）。
   - 多网盘/挂载目录高级同步与多端进度同步。

### 2.3 本地缓存位置与持久化机制
- **RevenueCat 本地缓存**：
  - 持久化介质：`UserDefaults.standard`
  - 存储前缀：`com.revenuecat.purchases.`（内部包含序列化的 subscriber 状态、etags、离线缓存收据）。
- **Keychain 跨进程与凭据共享**：
  - 钥匙串访问组：`M3U66M2SM4.com.snowlee.eplayerx.shared`
  - 网盘与服务器凭据服务：`com.snowlee.eplayerx.server-credentials-v2`（加密保存百度/光鸭/WebDAV/SMB 等账号密码与 Token）。

### 2.4 服务端校验环节与网络接口
EplayerX 的商业化网络交互全部基于标准 HTTPS REST API：
1. **RevenueCat 主网关**：
   - 域名：`https://api.revenuecat.com`
   - 核心接口：
     - 查询/拉取订阅信息：`GET /v1/subscribers/{app_user_id}`
     - 校验收据：`POST /v1/receipts`
2. **容灾与备份网关**：
   - 域名：`https://api.rc-backup.com/`（代码中显式配置为中国区或网络异常时的 fallback 域名）。
3. **动态 Paywall 配置**：
   - 域名：`https://api-paywalls.revenuecat.com`
4. **客户端认证凭证**：
   - 硬编码于 `Info.plist` 中的公开 SDK Key：`RevenueCatAPIKey` = `appl_SuaCRZFrCoSfMjznODihGrmqiGq`
   - 请求头格式：`Authorization: Bearer appl_SuaCRZFrCoSfMjznODihGrmqiGq`

## 3. 协议与云盘连接层

### 3.1 本地局域网协议
- **SMB 2/3**：
  - 实现依赖：内置 `AMSMB2.framework` (`s6AMSMB211SMB2Manager`)。

## 5. 可测性分级与静态审计结论

### 5.1 可测性分级：**S2** (标准 SDK 托管校验与高可测性)

### 5.2 判定依据与审计证据
1. **本地自治播放管线（非 S3）**：
   - 核心解码（FFmpeg / libdav1d）、音频（TrueHD / DTSX / ObjectAudio）、字幕（libass）以及图形渲染（libplacebo + MoltenVK）均完整集成于客户端本地，播放时不依赖服务端提供 DRM 密钥、解密 Token 或代理转码流。
2. **公开且可控的托管校验链路（典型 S2）**：
   - Pro 权限严格由 RevenueCat SDK 的 `CustomerInfo` 驱动。
   - 客户端在 `Info.plist` 中公开了公钥 API Key (`appl_SuaCRZFrCoSfMjznODihGrmqiGq`)，请求链路为纯 REST JSON。
   - 在开发与测试环境下，支持通过 Xcode StoreKit Configuration (`.storekit`) 在本地沙盒直接注入测试交易，也可以通过网络代理工具（如 Charles / mitmproxy）拦截 `api.revenuecat.com/v1/subscribers/` 返回上述夹具 JSON，从而无侵入式、极低成本地验证客户端全部 Pro 状态机分支。
