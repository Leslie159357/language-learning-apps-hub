## 1 技术栈 / 播放 / ASR / 扩展

### 1.1 技术栈

原生 **Swift + SwiftUI**（`dalaoE/*.swift`），`@Observable` + **SwiftData**（`PersistentModel`、`SwiftData.framework`、`@Model` 宏展开的 `persistentBackingData`）。

系统框架（完整 LC_LOAD_DYLIB）：`AVFoundation / AVFAudio / AVKit / CoreMedia / WebKit / SwiftData / StoreKit / NaturalLanguage / **Translation** / `_Translation_SwiftUI` / CryptoKit / PDFKit / AppIntents / UIKit / PhotosUI`。

**关键否定证据（决定分级）**：
- **没有任何自有后端域名**。全部 URL 只有第三方平台（bilibili / youtube / douyin / xiaohongshu / ytimg）和 `apps.apple.com`。
- 无 `WebSocket`、无 `CloudKit` / `iCloud` / `NSUbiquitous` 字符串 → 没有云同步、没有服务端账号。
- 无 `Alamofire` / 无自建 `APIClient`（对比另两个 App）→ 唯一的网络出口是"抓平台字幕/取流"。

⇒ **这是一个纯本地的单机 App，会员态完全由 StoreKit 2 交易决定。**

## 2 付费墙判定链

### 2.1 产品 ID（3 档，全部 StoreKit 2）

| Product ID | 档位 | 文案 |
|---|---|---|
| `com.dalaoE.dalaoE.plus.monthly` | 月付 | `月付`、`月付、年付会自动续费。` |
| `com.dalaoE.dalaoE.plus.yearly` | 年付 | `年付`、`取消需在到期前至少24小时。` |
| `com.dalaoE.dalaoE.plus.lifetime` | 永久 | `永久`、`永久会员只付一次，不会自动续费。` |

档位枚举 `DalaoPlusPlan`：`monthly | yearly | lifetime`。

### 2.2 校验函数名 / 判定位置

**唯一的判定源是 StoreKit 2 的本地交易，没有任何校验服务器。**

参与类型：`DalaoSubscriptionStore`（`@Observable`，`_TtC6dalaoE22DalaoSubscriptionStore`）、`DalaoPlusPlan`、`LearningMemberAction`。

`DalaoSubscriptionStore` 的完整存储属性表（从 Swift 反射元数据按声明顺序复原）：

```
_products              [Product]        已加载的 SKU
_purchasedProductIDs   Set<String>      当前有效订阅的 productID 集合  ← 判定核心
_isLoadingProducts     Bool
_isCheckingEntitlements Bool             "正在确认会员状态，请稍等。"
_purchasingPlan        DalaoPlusPlan?
_isRestoringPurchases  Bool
_hasLoadedProducts     Bool
_statusMessage         String?
transactionUpdatesTask Task             监听 Transaction.updates
refreshTask            Task
entitlementRefreshCount   Int            手动刷新计数（UI 重算触发器）
entitlementRefreshRevision Int
syncPurchases          () -> Void       = AppStore.sync()（"恢复购买"）
```

用到的 StoreKit 2 API（mangled 符号，逐条实测）：
```
Transaction.currentEntitlements        ← 冷启动/回前台时的权威来源
Transaction.updates                    ← 交易变更流
Transaction.productID / expirationDate / revocationDate / isUpgraded
Transaction.finish()
Product.products(for:)
Product.purchase(options:)  → .success(VerificationResult<Transaction>) / .userCancelled / .pending
VerificationResult（含 VerificationError 分支，即校验 .verified 才认定有效）
AppStore.sync()
```

**判定链（证据级复原）**：
```
App 启动 / 回前台 / 收到 Transaction.updates
  → for await result in Transaction.currentEntitlements
  → guard case .verified(let t) = result   （未通过 JWS 验签的交易被丢弃）
  → 过滤 t.revocationDate == nil && (t.expirationDate == nil || t.expirationDate > now)
                                                          ↑ lifetime 无 expirationDate
  → purchasedProductIDs.insert(t.productID)
  → 视图层读 purchasedProductIDs / DalaoPlusPlan 决定是否放行
```

会员专属动作的错误枚举含 `membershipRequired`（二进制度字符串，与 `LearningMemberAction` 同类元数据相邻），即：**受保护动作在客户端 `guard` 里抛 `.membershipRequired`，不发起任何网络请求**。

UI 层直证：
- `正在确认会员状态，请稍等。` / `正在确认会员状态。`（`isCheckingEntitlements`）
- `会员已开通。` / `永久会员已开通。` / `当前方案已开通。`
- `开通会员后可用。`（显示中文翻译） / `开通会员后，可导出双语字幕。`
- `查看月付、年付和永久会员。`、`价格以苹果商店显示为准。`
- `未找到购买记录，请确认购买账户。`、`购买未能确认，请恢复购买。`（`VerificationResult` 失败分支）

### 2.3 额度/点数怎么记：**没有额度制**

- 二进制中不存在 `credit` / `quota` / `remaining` / `used` / `points` 任何一处额度语义（`points` 命中的全是 `CGPoint` / 词典条目 `point out`）。

## 4 可解锁分级

**综合结论：A 级（纯本地，可完整解锁）；但对 Loon 而言是"零收益"（无网可改）。**

### A 级——成立，证据链完整

1. **判定源本地**：`Transaction.currentEntitlements` 是设备本地 JWS（Apple 签名，离线可验），不经任何自家服务器。
2. **无本地与服务端状态同步**：无 entitlement 接口、无账号、无 CloudKit → 不存在"服务端覆盖"。
3. **门禁在客户端 guard**：`membershipRequired` 是客户端错误枚举；受保护动作（翻译显示、双语导出）在发出动作前就被拦。
4. **功能本身是本地能力**：Apple `Translation` 框架翻译、`SpeechAnalyzer` 识别、SRT/VTT 导出（`PDFKit` 打印分享）——全部在本机完成，**打开即真解锁**，不是"假 UI"。
5. 付费墙覆盖的功能面（从全部"开通会员"字面量反推，**只有两个门，且都在 LearningView 内**）：
   - **门 1**：`显示中文翻译` / `解锁中文翻译`（拦在翻译动作前，文案 `开通会员后可用。`）
   - **门 2**：`导出双语字幕`（`开通会员后，可导出双语字幕。`、`lesson.exportTranscript`）
   - 其余（跟读、录音、播放控制、句子收藏、生词本、分类、稍后读、SRT/VTT 导入、设备端自动字幕）**免费即可用**
   - 即：会员买的是"Apple 设备端翻译 + 双语导出"，不是"用量"。这解释了为什么它不需要服务端——翻译是 iOS 自带的本地能力，成本在用户设备上。

⇒ 一旦绕过 `purchasedProductIDs` 判定，得到的是**完整、真实、可离线**的会员能力，没有任何服务端会来打脸。这是三案中唯一干净的 A。

### 为什么 Loon 无效（并列结论）

- 无 entitlement 请求 → **没有可改写的响应**。
- 唯一"能改"的是 bilibili/youtube 的响应（改视频列表/字幕），与会员无关，且平台侧有风控。
- 反向思路（用 Loon 伪造 `buy.itunes.apple.com` 的 verify 响应）也走不通：StoreKit 2 的 JWS 由系统守护进程 `storekitagent` 验签，签名根是 Apple，**不经过用户态网络栈**，Loon 抓不到也改不了。

## 5 务实落点

### 5.1 Loon：**没有落点**

```
[Host]
# 无。付费墙不产生任何网络请求，改域名/改字段均无效。
```
如果一定要写规则，只能做"去掉广告位/解锁视频列表"这类与会员无关的事，收益与成本不成比例。**结论：此 App 不适合 Loon 路线。**

### 5.2 真正的落点：本地补丁（TrollStore / 越狱 / 重签注入）

按性价比排序：

1. **Hook `DalaoSubscriptionStore.purchasedProductIDs` 的 getter**（最干净）
   - 返回恒包含 `com.dalaoE.dalaoE.plus.lifetime` 的 `Set<String>`。
   - 只影响读取侧，`Transaction.updates` 与 `refreshTask` 仍照常跑，不会互相打架。

2. **Hook `DalaoSubscriptionStore` 的 `refresh()` / `syncPurchases()`**，在 `currentEntitlements` 之后强制插入伪造 productID。
   - 缺点：`isCheckingEntitlements` 会闪一下，`正在确认会员状态` 短暂出现。

3. **Hook `Product.purchase` 的返回**（`.success(.verified(fake))`）
   - 不推荐：`Transaction` 是 `struct` 且无公开 `init`，构造需要内存摆位；且 `Transaction.updates` 后续会覆盖。

4. **直接改分支**：patch 掉 `guard ... else { throw .membershipRequired }` 的两条路径（翻译入口、导出入口）。
   - 优点：不碰 StoreKit，最稳；缺点：功能点新增时要重新找。

实现注意（与仓库规范一致）：
- 纯 SwiftUI + `@Observable` + SwiftData（iOS 18+），**不要**用传统 OC `%hook` 去 hook `DalaoSubscriptionStore`（Swift 类无 ObjC 运行时暴露，`class_getInstanceMethod` 找不到）。
- 走 Swift 符号钩（`MSHookFunction` 对 `_$s6dalaoE22DalaoSubscriptionStore...vg` 的 getter 实现地址）或 LoadControl 弱加载注入 dylib。
- 注入后**不要**动 `Transaction.finish()`：否则真实交易状态机错乱，`Transaction.updates` 会把 UI 打回未购。

### 5.3 一句话结论（给决策用）

**大佬英是"本地 StoreKit 2 单机付费墙"：Loon 完全无用，本地补丁一击即穿且解锁的是真功能（设备端翻译 + 双语字幕导出）；但也因为没有服务端，任何"账号共享/家庭共享"式的玩法都不存在——只能改包。**
