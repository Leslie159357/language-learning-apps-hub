## 1. 技术栈与架构

- **ObjC 为主 + Swift 混编（模块名 `EuDic`，与「德语助手」共享同一 Swift 模块）**。经典 UIKit + NIB 体系：包内 200+ `.nib`（`AboutUsHeaderView`、`AddSubscribeCell`、`ChannelCell`、`ReciteConjugaisonCell`…），说明布局用 XIB 而非纯代码。
- **随包动态框架（仅 3 个）**：
  - `Frameworks/FSPlayer.framework` —— **ffmpeg 内核播放器**（`SC_Info` 目录 + 字符串含 `#EXT-X-KEY:`、`decrypt_alloc`、`avformat` 系）→ 支持 HLS + AES-128 密钥的加密流。
  - `Frameworks/Tquic.framework` —— 腾讯 QUIC/TQUIC 传输库（弱网下载加速）。
  - `Frameworks/GDTMobSDK.framework` —— 腾讯优量汇广告。
- **静态链接进来的重件**（从类表可见）：ReactiveCocoa（`RACSignal/RACSubscriber/RACSubscriptionScheduler`）、MMKV（键值缓存）、Masonry、SDWebImage、FMDB/WCDB、UMeng（统计，`ulogs.umeng.com`）、微信/QQ/微博 SDK（`wx59f68268cc23b07d`、`openmobile.qq.com`）。
- **扩展 5 个（含 1 个 watchOS 扩展）**：
  `WidgetExtension_de`、`IntentsExtension_de`（Siri）、`NotificationServer_de`（通知服务）、`OfflineSpeechDownloader_ting_de`（离线语音包下载）、`watch_de Extension`（Watch App 扩展）。
- **资源**：OpenCC 全套 `*.ocd2`（繁简/异体转换）、`HTMLRes/reader.js` + `TranslateScript/userscript`（阅读器与划词翻译注入脚本）、`eudic_ting_1..44.mom`（44 个 CoreData 版本迁移模型）。
- **架构判断**：内容（音频/字幕）是"服务端下发 URL + FSPlayer 流播"；AI 能力（AI 讲解、口语评测、AI 搜索、写作）全部命中 `/api/v5/ai/*` 服务端接口；VIP 状态是「服务端 license 包 + 端上缓存布尔」双轨。

## 2. 付费墙判定链

### 2.1 商品 ID

**包内无任何硬编码 SKU**（全量正则检索 `[\w-]+\.(vip|sub|iap|member)` 只命中无关符号）。商品由服务端下发：

| 接口 | 证据 |
|---|---|
| `GET /api/v2/appsupport/IapProductList` | 字面量存在于 `__cstring`；无参 GET → HTTP 500，POST → 405（方法限 GET，需 app 标识参数） |
| `GET /api/v5/ting/GetInAppPurchasePromotion?id=%@` | 内购促销位 |

购买链路是 **StoreKit 1（`SKProductsRequest`）**，不是 StoreKit 2：
`EUPurchaseManager.productsRequest:didReceiveResponse:` @0x101237e58
`EUPurchaseManager.paymentQueue:updatedTransactions:` @0x101235f38

### 2.3 本地标记

| 键/字段 | 性质 | 证据 |

### 2.4 服务端 entitlement 下发路径

```
POST /api/v2/license/add            ← 绑定/新增授权
POST /api/v2/license/refresh        ← 刷新授权（实测 POST 空体 → 401 Unauthorized，problem+json + traceId ⇒ .NET 后端）
GET  /api/v2/license/info?productid=%d
POST /payment/IapPurchaseComplete   ← 内购完成上报
GET  /api/v2/auth/UserInfo          ← 用户信息（VIP 字段载体）
```

`is_vip` / `vip_type` 是**服务端返回、端上缓存**的两级结构；`activateFailed:` + `requestFinished:responseString:` 说明「Apple 交易成功 ≠ 激活成功」，还需服务端二次授权。

## 4. 可解锁面分级

| 级 | 内容 | 证据 | 结论 |
|---|---|---|---|
| **A** | `AppDelegate.isVip` + `KEY_CURRENT_IS_VIP_STATUS` 缓存 | 0x1000B80EC / `__cstring` 键 | 改这个能让 UI 变身会员（隐藏购买入口、显示 VIP 皮肤、解锁"试听提示"分支）。**但授权包未变，服务端仍按账号判断**，AI 类功能会立刻打回（`needVip` 来自服务端）。 |
| **B** | 列表/详情 JSON 中的 `is_vip`、`vip_type`（`/api/v5/ting/EicoHomePage`、`/api/v4/ting/articles…`） | 字段名在串池；接口需登录态（401），**响应体未取得** | 把 `is_vip:1 → 0`、`vip_type:N → 0` 可让列表去掉"会员"角标、允许进入详情页。**是否真能播放取决于 `/api/v4/ting/archive/…` 是否对该条目下发音频 URL**——此项未验证（需账号）。若 VIP 音频 URL 由服务端按订阅态才返回，则 B 级到此为止。 |
| **C** | ① AI 讲解/口语评测/AI 搜索/AI 对话；② 精品课（jingting）与考试；③ AI token 额度 | `/api/v5/ai/*`、`/api/v5/jingting/*`、`/api/v5/ai/AiTokenReset`、`courseExam` 的 `needVip`/`noBalance` 参数 | 服务端执行 + 服务端计量，重写无意义。 |
| **C（内容侧风险）** | 加密音频 | `FSPlayer` 含 `#EXT-X-KEY:` / `decrypt_alloc`；`/api/v4/ting/archive/…&cdn=auto` | 若 VIP 音频为 HLS+AES-128 且 key URI 由服务端按订阅态签发，改 JSON 无效。未取得样本，**按风险标注，不作结论**。 |

**总判定：主体为 C（AI + 精品课 + 额度），首页/详情存在 B 级"去会员标记"空间。** 不存在"纯本地开关即全解锁"的 A 级面。

## 5. 务实落点

### 5.1 值得写的 Loon 规则（B 级，收益＝去标记/进详情）

```ini
[mitm]
hostname = api.frdic.com

[rewrite_local]
# 首页聚合 + 文章列表/详情：把会员标记清零
^https:\/\/api\.frdic\.com\/api\/v5\/ting\/EicoHomePage url script-response-body ting_vip.js
^https:\/\/api\.frdic\.com\/api\/v4\/ting\/(articles|article)\/ url script-response-body ting_vip.js
```

```js
// ting_vip.js
let o = JSON.parse($response.body);
const fix = (n) => {
  if (!n || typeof n !== 'object') return;
  if (Array.isArray(n)) return n.forEach(fix);
  for (const k of Object.keys(n)) {
    if (k === 'is_vip' || k === 'isvip' || k === 'vip_type' || k === 'needVip' || k === 'isVip') n[k] = 0;
    else fix(n[k]);
  }
};
fix(o);
$done({ body: JSON.stringify(o) });
```

**效果上限**：列表不再显示"VIP"角标、详情页不再弹购买引导；**VIP 音频是否能播未验证**（取决于 `/api/v4/ting/archive/…` 的返回）。

### 5.2 不要指望的方向

- `/api/v2/license/*` 全部需要账号 token（实测 `POST /api/v2/license/refresh` → **401**，`problem+json` + `traceId`，.NET 后端）。改这条只能伪造授权包，且 `activateFailed:` 说明端上会对授权结果二次判定。
- `/api/v5/ai/*` 与 `/api/v5/jingting/*`：额度/权限在服务端，`noBalance`/`needVip` 是服务端返回值而不是端上计算值。

### 5.3 本地补丁（非 Loon）

若走 dylib/TrollStore：
- hook `-[AppDelegate setIsVip:]`（0x1000B80FC）强制传 `YES`，或 hook `-isVip`（0x1000B80EC）返回 `YES`；
- 同步写 `KEY_CURRENT_IS_VIP_STATUS`。

效果 = A 级：皮肤/入口全开，**AI 与精品课仍被服务端拒绝**。

### 5.4 卡点总结

1. 授权链「StoreKit 交易 → 服务端 `license/add|refresh` → 端上激活」三段式，缺一段即失败。
2. 内容（音频）走 `archive + cdn=auto`，若为 HLS 加密流则 key 在服务端手里。
3. AI 能力的 `needVip`/`noBalance` 由服务端随响应返回，端上无法伪造。
