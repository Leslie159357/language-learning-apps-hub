# 每日德语听力 深度架构分析报告

## 一、 技术栈判定

根据 `app_graph.yaml`、`recon/source_files.txt` 与原生符号证据判定，每日德语听力（Bundle ID: `com.eusoft.ting-de`，版本 26.10.2，最低系统要求 iOS 15.0）属于一款**多语言重度混合工程**，融合了 Objective-C 历史基建、现代 Swift 业务重构以及自编译 C/C++ 离线推断内核。

- **语言与架构选型**：工程由 Swift（428 个源文件）、Objective-C（92 个源文件）与 C/C++（464 个源文件）混编而成。既保留了欧路经典 SDK 体系（`EuSoft/dev/ting/ios/...`），又大量吸纳了 SnapKit 布局（`ConstraintMakerRelatable.swift`）与 Lottie 动效。
- **自研多媒体与网络加速内核**（证据来源于 `app_graph.yaml` 的 `frameworks`）：
  - `Payload/ting_de.app/Frameworks/FSPlayer.framework`：自研高性能多媒体播放框架，内嵌专属 Metal 着色器库 `default.metallib`，承担专业级音频波形与字幕高刷渲染。
  - `Payload/ting_de.app/Frameworks/Tquic.framework`：集成基于 QUIC 协议的高速网络传输库，针对弱网与高延迟环境优化听力音频的秒开与边下边播。
- **端侧 AI 推断引擎**：工程内嵌了完整的 **ONNX Runtime** 核心及其 CoreML 转换层（证据源路径：`/1/s/onnxruntime/core/providers/coreml/...`，相关类：`AllocateReusedOrtValueIfNotAllocatedHelper`、`PartitionOnnxFormatModel`），用于端侧离线语音对齐与断句打分。
- **依赖 SDK 与动态库**：
  - 广告 SDK：腾讯优量汇（`Payload/ting_de.app/Frameworks/GDTMobSDK.framework`）、有道广告 SDK（`ad-sdk-config.youdao.com`）。
  - 社交开放 SDK：小红书 OpenSDK（`XHSOpenSDK.m`）、新浪微博 SDK（`open.weibo.com`）。
  - 网络基建：保留了 AFNetworking 历史组件（`AFHTTPSessionManager`、`AFHTTPRequestOperationManager`）。
- **规模证据**：主二进制 `ting_de` 体积达 53.69 MB，包内包含 1475 个资源文件与 4 个动态 Framework。采用多进程扩展矩阵，挂载 4 个系统 App Extension（`IntentsExtension_de`、`NotificationServer_de`、`WidgetExtension_de`、`OfflineSpeechDownloader_ting_de`）及 Apple Watch 扩展。

## 二、 模块分层

基于 `recon/all_classes.txt` 抽取的 1946 个原生类归纳，整体架构呈现以下层级：

1. **启动、配置与场景调度层**：管理系统环境适配、Widget 刷新、快捷指令及富文本通知。
   - 真实类名：`ASIAutorotatingViewController`、`ASAuthorizationController`、`EUWidgetKitManager`、`EUNotificationHandler`、`EURemotionStudySettingsController`、`AboutUsViewController`、`CPTemplateApplicationScene`。
2. **业务服务与音频管理层**：主导听力转录、AI 对话协同、离线资源后台下载与配音逻辑。
   - 真实类名：`EUFileSpeechDownloadManager`、`EUFileSpeechRecognizeManager`、`EUSpeechManager`、`EUVoiceTranscribeManager`、`TingFileSpeechRecognizeManager`、`DubbingSubtitleManager`、`EUAIChatManager`、`EUAIKitManager`、`SpeechTranscriberManager`、`DictationTranscriberManager`。
3. **数据持久与多端同步层**：处理欧路云冲突解决、听力进度断点记录与离线词库映射。
   - 真实类名：`EUCloudDocument`、`EUCloudManager`、`EUCloudConflictFilesAlertController`、`ArticleDictationWordModel`、`CacheCallbackCoordinator`、`CacheManageViewController`、`CaptureWordModel`、`CompactUserInfoModel`、`DotLottieCache`。
4. **网络传输与媒体加载层**：整合 QUIC 传输加速、阿里云盘直连、分片音频加载。
   - 真实类名：`AFHTTPSessionManager`、`AFHTTPRequestOperationManager`、`AFNetworkReachabilityManager`、`AVAssetResourceLoadingRequest`、`ApiKnowledgeCircleArticleResult`、`ApiKnowledgeCircleCommentResult`、`AliPanVideoPlayInfoModel`。
5. **UI 与交互呈现层**：涵盖全屏播放台、逐句精听滚轮、配音广场与记忆翻牌。
   - 真实类名：`ArticleAudioFullScreenController`、`ArticelReaderContentScrollView`、`ArticleContentTimestampTextView`、`ArticleDictationView`、`ArticleDictionaryViewController`、`DubbingMainViewController`、`EUAIChatViewController`、`CardStackView`、`EUWordCardController`。

## 四、 网络与 API 契约

依据 `recon/endpoints.txt` 梳理出的核心服务契约：

1. **欧路自有云端 API 契约**：
   - `api.frdic.com` / `c.frdic.com`：欧路核心业务网关，提供海量德语听力文章音频（`http://api.frdic.com/api/v3/media/mp3/`）、云端语音听写识别（`https://api.frdic.com/transcribe/recognize`）、查词接口（`/api/v2/dicts/search`）以及离线词库分发（`/api/v2/dictlib/download`）。
   - 网盘授权桥接：`https://api.frdic.com/alipan/oauth`、`https://api.frdic.com/BDPan/oauth`，负责云盘 OAuth 换票，支持用户将网盘中的私人听力文件直接引入。
   - `dict.eudic.net` / `static.eudic.net`：承担听力文章详情 H5、视频微件资源与富文本解析载体。
2. **第三方与 AI 大模型接口**：
   - **大模型支持**：`https://api.deepseek.com`，直接集成 DeepSeek API，用于听力篇章 AI 精讲、语法解惑与口语模拟。
   - **TTS 语音合成**：`https://southeastasia.tts.speech.microsoft.com/cognitiveservices/v1`（微软 Azure 认知语音服务）。
   - **机翻能力**：`https://fanyi-api.baidu.com/...`、`https://api.microsofttranslator.com/...`。
   - **云盘 OpenAPI**：`https://openapi.alipan.com/adrive/v1.0/...`，实现阿里云盘文件直链拉取与分片下载。
   - **广告与统计**：`ad-sdk-config.youdao.com`、`aaid.uyunad.com`、`GDTMobSDK`。

## 五、 源文件拓扑与工程线索

根据 `recon/source_files.txt` 提取的 1126 条应用源文件与工程特征分析：

- **深度演进的多 Target 架构**：除了主 Target `ting_de`，工程拆分出 `OfflineSpeechDownloader_ting_de.appex`。将音频网络流的分片离线下载置于独立 Extension，避免前台因网络抖动和长时间下载被系统挂起（Watchdog 杀掉），展现了成熟商业级工程的设计思路。
- **多语言跨架构协同**：工程在保留 `EuSoft/dev/ting/ios/...` 经典 Objective-C 沉淀的同时，把端侧深度学习网络通过 C++ ONNX Runtime 封装为底层库，上层界面则使用 Swift + SnapKit 快速迭代。
- **命名规范强统一**：全局统一采用欧路专属的 `EU` 前缀（如 `EUCloudManager`、`EUAIKitManager`、`EUStoreKitTool`）；听力文章业务统一以 `Article` 命名；配音模块统一以 `Dubbing` 命名，规范性极强。

## 六、 对自研的参考价值

### 1. 值得借鉴的设计
- **专用播放器与 QUIC 加速融合**：自研 `FSPlayer.framework` 结合 Metal 进行波形绘制，并引入 `Tquic.framework` 进行 QUIC 协议网络加速，彻底攻克了传统 HTTP 流式长音频在蜂窝移动网络下首帧缓冲慢的痛点。
- **独立后台下载进程**：通过 `OfflineSpeechDownloader_ting_de.appex` 将大文件、批量离线听力资源的下载剥离到主 App 之外，避免了前后台切换被系统杀死的风险。
- **端侧 ONNX 推理落地**：直接将 ONNX Runtime 与 CoreML 算子构建（`onnxruntime/core/providers/coreml/builders/`）打包进主工程，为端侧低时延跟读评测与本地断句对齐提供了坚实基础。

### 2. 历史包袱与不宜照搬
- **历史冗余网络栈残留**：代码中依然充斥着早期的 `AFHTTPRequestOperationManager` 和 `ASIAutorotatingViewController` 历史包袱，造成符号重叠与维护负担；自研团队应彻底基于 Swift Concurrency 与原生 `URLSession` 搭建纯轻量网络层。
- **包体积与广告 SDK 臃肿**：主二进制突破 53 MB，集成了优量汇、有道广告、多套埋点 SDK，导致整体启动链路与资源消耗过重。
