## 2. 付费墙与额度判定链

### 2.1 商品 ID：不在客户端硬编码
客户端**不持有**任何 `com.eusoft.ting.*` 订阅 ID。商品表由服务端下发：

- `/api/v2/appsupport/IapProductList`（拉 IAP 商品列表）
- `/api/v2/appsupport/RecommendProducts`
- `/api/v5/ting/GetInAppPurchasePromotion?id=%@`（促销）
- 本地仅缓存"当前商品号"：默认键 `MAIN_ProductID`（字符串，`__objc_methname` 段）

购买链路是**服务端下单型 IAP**，不是纯 StoreKit：
- `/payment/mobile_ting?appkey={appkey}&userid={userid}&vc={vc}&lt={lt}&ft={ft}&tw={tw}&useragent={useragent}&meta=pay_app&paymethod=iap`（VIP 下单页）
- `/payment/IapPurchaseComplete`（购买完成回执，服务端核销）
- `/api/v5/jingting/purchased`（已购列表，`orderByPurchased=true`）
- 深链入口：`cmd://purchaseInApp`、`cmd://user/iap?`、`cmd://user/restore_iap?`、`cmd://user/vip_buy`、`cmd://ai_purchase`

### 2.6 付费墙实际卖什么（UTF-16 中文串，直接证据）
- `加入VIP畅享无限译文，解锁全部功能`
- `字符超出上限，开通VIP可以提高到5万字。`

## 4. 可解锁分级

分级定义：**A**=纯本地判定，改写/补丁即可完全生效；**B**=客户端有判定点可改，但部分能力依赖服务端复核/下发；**C**=判定与内容都在服务端，前端改写只影响展示。

### 结论：**B 级（偏 B−），整体不可"全解锁"**

**支持 B 的证据**
1. `isVip` 是本地属性，值来自 `KEY_CURRENT_IS_VIP_STATUS`（默认键名 + `TB,N,V_isVip` 属性编码 = 本地 BOOL 落点）。改这个键/patch getter 会让所有 **UI 层** VIP 入口放行：去广告、译文入口、AI 入口、5 万字上限提示。
2. 免费译文额度是**本地计数**：`key_translate_article_count` / `key_translate_article_total_present_count`。把 total 调大或 count 归零即可无限翻译（本地判定路径）。
3. `tingvipendtime` 是本地到期时间戳，无本地签名/校验痕迹（未发现 HMAC/摘要比对选择器）。

**拉回 C 的证据（硬墙）**
1. **AI 额度在服务端**：`chat_quota_remains` 随 `/api/v5/user/profile` 或对话应答下发，且对话接口出错时服务端直接回 `needVip`/`noBalance`（选择器 `...needLogin:noBalance:needVip:errorMsg:`）。客户端改不了剩余次数。
2. **付费课程/专享内容在服务端**：`purchased_courses`、`/api/v5/jingting/purchased`，媒体由 `/api/v3/media/mp3/`、`/api/v4/ting/archive/` 按 article id + `agent` 下发，VIP 专属音频是否放行由服务端决定（未见客户端解密/本地授权分支）。
3. **商品与核销在服务端**：商品列表来自 `IapProductList`，核销走 `IapPurchaseComplete`；伪造 StoreKit 交易无法完成核销，VIP 不会真正到账（除非同时改 `KEY_CURRENT_IS_VIP_STATUS` 让客户端自嗨）。
4. **每日更新库本身是服务端内容**：`/api/v5/ting/recentlyupdated`、`/api/v4/ting/Homepage` 类接口按天/按频道下发，客户端无本地内容库（1497 文件里无文章/音频缓存随包）。

## 5. 务实落点

### 5.1 Loon 可改的（按性价比排序）
1. **去广告 + 解锁 UI 层 VIP**：`api.frdic.com` 的 `/api/v5/user/profile` 响应里把 `is_vip`→1、`vip_type`→`forevervip`、`user_purchase_status`→已购枚举。效果：VIP 图标全亮、广点通初始化被跳过（`开通VIP即可移除该广告` 的本地判定读 `isVip`）、译文入口可点。
   - URL 正则建议只匹配 `^https:\/\/api\.frdic\.com\/api\/v5\/user\/profile`，body 用 `json-body` 改写，避免污染其它接口。
2. **译文次数**：本地计数不在网络层，Loon 改不到；需本地补丁（见 5.2）。
3. **AI 对话额度**：可尝试改写 `/api/v5/user/profile` 里的 `chat_quota`/`chat_quota_remains`，但对话接口自身会二次校验（服务端返回 `needVip`/`noBalance` 时客户端只能弹窗），**大概率只改 UI 数字**。

### 5.2 本地补丁可做的
- Hook `-[<VIP 管理类> isVip]` 直接 `return YES`（类名未在字符串中显式落地，需在 Ghidra 里从 `setIsVip:` 的 xref 反查宿主类 —— 本次未跑通，标注为待办）。
- 或直接写 `NSUserDefaults`：`KEY_CURRENT_IS_VIP_STATUS=1`、`tingviptype=forevervip`、`tingvipendtime=<远期时间戳>`、`key_translate_article_total_present_count=999999`。
- **注意**：`EUPurchaseManagerTing` 会在启动/回前台按 `NOTIFICATION_VIP_STATUS_UPDATE` 用服务端 profile 覆写这些键，补丁需同时挂住刷新逻辑，否则重启即失效。

### 5.3 真正卡在服务端的（直说）
- **AI 解析 / AI 对话的真实推理**：额度与调用都由服务端记账，改前端只是把"余额不足"弹窗骗过去，请求到了服务端仍被拒。
- **付费课程与专享频道音频**：内容与授权都在 `api.frdic.com`，客户端没有离线授权文件，Loon 改响应无法凭空造出音频。
- **每日更新的听力库**：本来就是服务端按天推的，不是"被锁住"而是"没下发"。
